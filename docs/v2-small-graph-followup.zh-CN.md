# V2 小图遗漏与补料复现优化

本轮基于本地实验提交 `3b13ba9`，保留原生 Java 后端、原有 3 秒整体期限和
16 次完整切环重试上限。未修改 CPU 调度、完整环准入规则或稳定 alpha。

## 修复

1. 普通单 SCC 的显式切点集合按稳定顺序去重，避免排列重复占用重试。
   多 SCC 可能从不同入口访问上游环，保留原遍历顺序；返回物、耐久和私有工具池也不做此合并。
2. 显式切环优先尝试距目标更远的有库存边界；排序时推迟连一批天然原料都不足的捷径。
   这只是候选排序，不作为可行性或不可行性证明。
3. 小型普通图预编译固定 DAG 策略，保留所有合格的单配方选择和原始循环边界。
   每个策略独立核算共享库存，只接受逐材料不增加且至少一项减少的补料改进。
   不把不可比较的材料替换当成改进。
4. 固定策略不依赖库存、请求数量或剩余搜索预算。没有副产物和状态工具的 DAG 中，
   增加库存只会降低上游需求，因此报告的补料仍能被同一策略完成。
   未选择的副产物备选不会禁用普通策略，但策略自身不主动生产副产物。

策略有三道结构上限：可达工作量 128（节点、配方和边的总计）、最多 5 个循环物品、
最多 256 个选择组合。超限整组跳过；未用配方的等价组合会去重。
策略编译按会话复用，不按合成次数枚举。额外工作为有固定上限的 `P × (V + E)`，
数量计算使用整批运算。该阶段会增加部分小图的计算成本，不宣称所有场景更快。

修复的可合误报为 `primary/3532`、`primary/5215`、`primary/5516`。
新增回归把这三张图的库存和请求量分别放大至 1、百万、万亿，均可执行。
例如：`focused/185` 的 M4 补料从 2 降到 1；`primary/506` 从 M3=1、M4=2 降到仅 M4=2。
补料测试同时验证用最小访问/搜索额度重新规划可合成。

## 仍然存在的边界

独立 DAG 搜索对剩余物理标记增加了“主产物需要被使用”和无环支持约束，未碰到状态上限：

- 10,000 张主产物图与 30,000 张聚焦图中，没有找到仍遗漏的无环可合方案，
  也没有找到可逐项减少补料的无环方案。这只是该有限图集的结论。
- 副产物图中仍有 2 个无环候选被报缺料，以及 6 个可减少补料的候选，两者有重叠。
  候选涉及已有主产物库存、替代生产及副产物联动；本轮未改动相关选择规则，不能宣称全部解决。
- 其余物理可达差异需要完整循环或其他超出上述 DAG 策略的路线。
  仅有一个存在的执行顺序不足以证明当前无序 CPU 调度安全，参见
  [环执行边界](v2-cycle-execution-boundary.zh-CN.md)。
- 256 组合上限、单配方策略及总体期限仍可能带来质量不足，不保证任意图上的全局 Pareto 最优。

## 验证与性能

- `test build --offline`：671 项测试，0 失败、0 错误、0 跳过。
- 两路线 Fib：114 例 × 3 轮全部可合；每轮合计时间中位数约 112 ms。
- 14 个 16–64 层、数量最高万亿的缺料用例均达到资源下界，单例中位数约 2.35 ms。
- 小图本轮 P99：主产物约 1.62 ms、聚焦约 0.49 ms、副产物约 8.79 ms；
  最慢约 44 ms。该统计包含 JVM/调度噪声，不代替整合包内的端到端测量。
- 没有新增原生库或下载依赖。
