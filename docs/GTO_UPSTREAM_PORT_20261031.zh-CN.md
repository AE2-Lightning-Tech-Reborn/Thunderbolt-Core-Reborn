# Thunderbolt Core 2.0.4-gto.1 上游移植

本次以普通 Forge `1.20.1` 的 `fa6d16e40ffdfc95ea0b8b74f9a35a2d87f1bc1e`
为来源，将适用更新移植到 Minecraft 1.20.1 / Forge 47.4.20 /
AE2-GTO 15.2610.31 / Java 21。`main`、`alpha` 仅作实现参考，不采用 GTL 分支。
上游代码许可证、原有署名及第三方声明保持原样。

## 变化

- 在应用 Mixin 前识别 Lithium、Canary、Radium 和本地已有的 LeanObject
  NBT 复制实现，避免复制方法的转换冲突；没有这些模组时继续使用 Core 优化。
  GameTest 按实际选定的复制实现检查深拷贝、原生容器及调用次数。
- 同 ID 材料发现纳入可达配方副产物，在后发现副产物时按原图导出预算重建；
  精确诊断选材计入当前副产物余额，不改变严格匹配或共享库存规则。
- 深层大数链认证加入有界依赖排序和单次认证内的不可变配方缓存，保留最终物料证明。
  递归撤销改为可复用的分段记录；宽输入枚举采用稀疏索引并保留顺序与取消检查。
- 完善批量补料、窄整数传播、精确成本下界、反馈向量与固定尾链处理。
  保留本地已认证方案在原生求解超时后的回退，以及纯计算证明的 CPU 时间额度；
  外层请求的取消和截止时间继续生效，没有增加工作或时间预算。
- 没有 CPU 限制的计划也保留可复用种子元数据；汇总数量使用精确累加，
  超出 long 时保留完整报告，显示溢出不会把可执行计划改成仅预览。
  极长紧凑标签使用科学计数法，完整提示保留所有数字。
- 新增统一请求接口 `CraftingRequestMenu`、`CraftingAmountMenu`，以及可选的
  `ExactCraftingBackend`、`ExactCraftingPlan`。确认页保留 GTO 原生 long 数量，
  支持完整数量重规划、返回数量输入、请求替换及算法跟踪清理。
  不可用的精确后端不得替换或取消正在计算的普通请求。
- 存储补充容量比较、保存数组和槽位扩容边界；小额精确请求复用 primitive 路径。
  Forge 同步保存返回隔离快照，之后的增量保存不能更改旧结果。
  保留本地已有的类型上限、末字节填充、进借位、重复键恢复和模拟只读语义。
- 进一步减少供应器队列、共享输入扫描、样板解包和稳定 CPU 索引的临时分配；
  共享种子的供应器选择保留唯一所有者与派发数量上限。
- 加入 Useless 当前大数、批量和智能翻倍协议的可选适配，按实际模组 ID
  `useless_mod` 延迟注册；缺少所需能力时继续普通派发。

## GTO 边界

继续使用本地 `GtoPlanningCalculation`、模拟库存、primitive `patternTimes()`、
Data Energistics 菜单入口和原生算法回退，没有用普通 AE2 的计算 Mixin 替换它们。

当前 AE2-GTO 的 `AEItemKey` 只保存物品与 `internedTag`，不表示普通 Forge AE2
独立的 `caps` 字段。输入缓存保护以 GTO 实际键身份为准；回归分别验证 NBT 变体、
GTO 物品键驻留以及不驻留的自定义键。这里没有为依赖新增一种能力序列化格式。

Core 只提供精确后端扩展 API，没有注册内置的任意大数 CPU 执行后端。
完整执行能力还取决于配套组件与实际 CPU，不能以接口存在替代整合包验证。

按当前约定排除上游 GTL 专属代码及普通 NeoECO 适配、注册、依赖和测试夹具增量。
现有 GTO 专属兼容代码没有恢复为普通分支实现。
