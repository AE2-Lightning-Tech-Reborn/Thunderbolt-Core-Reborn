# Core 规划专项：UNKNOWN 与预算边界（第③步）

本步承接[第①步契约](GTO_CORE_ALGORITHM_CONTRACT_20261102.zh-CN.md)，
以 `607c33e11374a7a49cb1a94bf28beeb2bb58ff83` 为入口，生产 before 仍是
`bd510967eb1f9a376d80e74695bef27bafbaa5dd` 的 `2.0.4-gto.4`。
本步连同只读审查后的修正共修改六个规划实现和四个对应测试文件，另交付本文及
[机器可读核验记录](baselines/core-planning-audit-20261102.json)。

## 缺口与修复

| 可复现缺口 | before 行为 | 修复后的行为 |
| --- | --- | --- |
| 图导出达到工作上限 | 将不完整导出替换为空图，缓存后返回 `HANDLED + null` 与目标缺料预览 | 返回未确定的 `DECLINE`，不发布或缓存空图；执行和模拟探测均适用 |
| 规划图规模截断或可选恢复超时 | 截断的诊断材料可能成为确定缺料；可选恢复超时不标记截断 | 恢复超时保留诊断但标记 `budgetExhausted/searchCutoff`；适配层对未认证成功的截断结果返回 `DECLINE` |
| CP-SAT 输入准备与结果认证 | 原生调用使用准备前的旧额度；整理期间取消仍会进入原生调用；可选超时被通用异常处理改成 `INTERNAL_ERROR` | 准备和认证长循环有检查点，进入原生前重新读取剩余时间，退出异常保持原义向外传播 |
| 原生桥入口与模型准备 | 稠密求解和反馈选择忽略已有中断；模型准备后重新开始计时 | 从入口固定截止点，准备阶段也消耗该额度；入口、长循环和实际求解前检查中断及截止点 |

`FastCraftingPlanner` 仍保留已认证可行的 incumbent，即使后续优化未完成；普通完整缺料
结果继续使用原有模拟回退。`DECLINE` 让现有路由选择后续候选，不能解释为确定无解。
这意味着以前收到保守缺料预览的超大/截断请求现在会进入已有候选回退路径；LT 增量
验收应覆盖该行为，而不是继续依赖截断预览作为无解证明。

未改动公开接口、公共状态枚举、deadline/取消的调用形状、循环数据格式、持久化或
批量结算。第①步冻结的 82 个共享生产/测试文件以及 EJECT、双 AE2 ABI 和身份键的
保留锚点逐项核对无变化。此次修改未重置调用方预算，也未调高任何生产/测试限额。

## 独立复现与测试

新增 `CpSatBudgetBoundaryTest` 六项测试，使用真实输入准备/异常边界，替换的仅是
原生回复：确定性地在输入整理阶段取消或使可选作用域到期，断言原生调用数为零；
原生返回时到期必须继续抛出原退出信号；真实隔离原生桥在已有线程中断时返回 UNKNOWN。
另将 40 ms 的受控输入准备计入原有 5 秒调用预算，核对传给原生的额度确实扣除准备时间，
不依赖求解速度或更大的超时获得通过。

新增 `FastPlannerUnknownOutcomeTest` 三项测试。65,537 个输入的实际规划图中全部物料
都已存在，独立逐输入扣减证明一次执行可行；实际图规模上限触发后仍必须 `DECLINE`，
不能报告目标缺失。另一项使用真实导出器达到上限，验证执行/模拟都不会缓存空图；
完整的普通缺料探测则继续生成原有模拟回退。

| 验证阶段 | 实际结果 |
| --- | --- |
| 修改前现有规划/算法/GTO 路由专项 | **1,291 通过，零失败/错误/跳过** |
| 首批新增七项回归，在旧生产实现上 | **6 项预期失败、1 项普通缺料对照通过** |
| 图导出独立回归，在该缺口修复前 | **1 项预期失败**：错误返回 `HANDLED` 缺料预览 |
| 可选恢复期限回归，在状态修复前 | **1 项预期失败**：未标记不完整搜索 |
| 修复后定向回归 | **16/16 通过** |
| 首次完整规划专项 | **1,299 通过、1 失败**，原因见下文，失败原件保留 |
| 最终完整 JUnit | **1,686 项：1,684 通过、2 跳过、零失败/错误** |

两项跳过仍为缺少可选 EAEP SuperMatrix 与 Useless 的真实接口输入；不计为通过。

既有 `oversizedAdapterExportReturnsConservativeSimulationPlan` 要求把不完整导出发布为
目标缺失，与本轮冻结的 UNKNOWN 契约冲突。现更名为
`oversizedAdapterExportDeclinesWithoutInventingMissingMaterials`，保留 66,000 个旁输出
和 2 秒上限，补充无输入配方一次执行即可生成目标的断言，并要求实际导出器被访问、
返回 `DECLINE` 且没有伪造缺料预览。没有删除夹具或放宽上限。
`SmallRecoveryBudgetStatusTest` 同样保留原图、工作量和超时夹具，只将超时后必须标记
未确定作为新的正确性断言，外部取消仍须原样传播。

既有通过的覆盖包括 Petri 执行认证的 1,000 个固定种子小网与独立逐次执行 oracle、
循环缺种子/现有库存、共享物理种子、催化剂和副产物、同 ID 不同变体及大数量等。
这些检查复用 Core 自己的库存回放与独立 oracle，未以 NeoECO 的结果作正确性判据，
也未把循环样本数当作独立 JUnit 项数相加。

## 第④步退回后的补充修正

频道审查卡启动失败且没有给出结论后，由独立只读子代理恢复审查；该代理没有修改
文件、运行构建或冒充频道审查成员。首次第④步结论为 **REJECT**：同一会话先前
已耗尽恢复时间，或主搜索恰好用完共享工作量时，恢复阶段直接跳过，未将仍有歧义
的缺料标为 UNKNOWN。第⑥步对批量修改的通过不解除这个规划阻塞。

在原生产代码上补充五项边界测试，得到 **3 个预期失败、2 个对照通过**。同会话先
探测 T1、再耗尽原有可选额度后探测 T23，原代码返回 B 缺 1 且不标截断；Fast 路由
对执行探测错误返回 `handled=true`。共享工作量仅为 4 的独立回归同样复现。该图的
库存为 A5/B14，独立逐次回放 `9T(A1/B5)` 两次及 `4T(A1/B2)` 两次，得到 T26，
每次输入均实际可用，因此 B 缺 1 不能作为无解结论。

修正后，恢复时间或共享工作量已耗尽且图仍含主输出争用、切环、种子顺序或副产物
选择时，保留诊断并标记不完整搜索；无争用、无环、无副产物的普通原料缺失及已
认证可行结果保留原行为。小图恢复另提供内部截断回调，贯穿 terminal 投影：只有
启用且尚未访问的后继确实被状态/深度界限阻止，才报告 cutoff；自然清空队列、刚好
用完最后工作单元、深度边界上的死路均不误标。旧内部重载继续保留，未新增公开或
LT 必需接口，未放宽任何生产限额。

新增同会话/共享预算和普通缺料/可行对照，补强实际深度、状态与精确工作量边界。
本轮两个测试类 **17/17** 通过。首次 Fast 红测夹具缺少 `IPatternDetails` 来源导致
NPE，已作为夹具错误单独保留；补上真实来源后仍在未改生产实现上重跑，实际失败
是 `handled=true`，没有把夹具错误充作缺口证据。各轮日志/XML 位于同一任务证据
目录的 `review4-recovery-*`，完整回归与复审结果由发行证据补记。

本步不作性能提升声明，不覆盖或重新发布 `.4` 正式包。受本次修正影响的规划基准
需要重新测量；旧批量基准保留其原制品身份和限制。最终完整重混淆包加载、
EJECT/GameTest、发行/PR 更新和 LT 新制品验收不能用开发映射 JUnit 或历史
`.3`/`.4` 正式包结果替代。
