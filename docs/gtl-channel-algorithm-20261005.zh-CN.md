# GTL 通道算法访问顺序优化（2026-10-05，第三轮）

对比基线 `f15dab0`。本轮优化通道图的编号和种子流回放，目标是减少大型网络重算的耗时。

## 实现与边界

发现网络时按 BFS 顺序保存节点，同时建立身份索引。构图直接复用这份索引，种子森林也从该顺序开始遍历，避免先遍历身份哈希集合、再按其随机散列顺序编号。相邻层的节点在数组中的位置更接近，供给节点先被发现。

返回的网络成员集合复用此次索引的键集合。发现结束后内部不再修改索引；下次计算创建独立索引。新增测试保留旧结果、扩展网络后重新计算，验证旧成员和旧流量不受影响。该集合仍按对象身份判断成员，其迭代顺序不属于通道分配契约。

生产图依次添加节点分裂边、成对物理连接、供给边和需求边。供给边的反向边因此连续位于节点输入邻接表的开头。种子流回放只扫描这一段；没有本地供给的中继立即停止扫描，避免遍历全部物理入边。多供给面仍逐边回放，容量为零的面不阻止其余面使用。此布局前提已写入种子算法注释，后续新增调用者应保持它。

种子仍产生容量可行的流量，剩余网络仍由精确残量最大流完成。图中容量、多方块共享需求、无线限流、禁止转发、部分加权获配和无需求网络的语义由回归检查覆盖。供给不足时，遍历顺序可能改变同等竞争设备的具体获配选择；本轮不建立新的优先级或公平性保证。

代价是 BFS 节点列表和递增扩容的身份索引增加了分配；结果的键集合还保留身份索引的整数值数组。不能把本轮描述为降低内存占用。

## 测量

完整样本见 [JSON](benchmarks/gtl-channel-algorithm-20261005.json)。Java 17.0.20、Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10，JVM 参数为 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。使用真实 AE2 节点和连接，计时包含生产通道分配，排除合成图创建及结果验证。

独立 JVM：每种图每个版本运行 3 个 JVM，前后顺序逐轮交换，每次预热 4 次、测量 12 次。表中取三个 JVM 各自统计量的中位数。nearest-rank p95 在 12 个样本中等于最大值。

| 场景 | 前/后 p50（ms） | p50 变化 | 前/后 p95（ms） | 前/后分配（MiB/次） |
| --- | ---: | ---: | ---: | ---: |
| 272,650 节点网格 | 878.008 / 571.764 | -34.9% | 975.449 / 757.899 | 101.208 / 104.290 |
| 226,898 节点树 | 591.356 / 267.517 | -54.8% | 843.900 / 394.469 | 76.173 / 78.056 |
| 20,266 节点梳状网络 | 20.954 / 16.275 | -22.3% | 48.621 / 26.084 | 6.292 / 6.456 |
| 532 节点加权需求 | 2.528 / 2.763 | +9.3% | 3.590 / 5.388 | 0.189 / 0.193 |

四种图的分配量分别增加 3.0%、2.5%、2.6%、2.1%。前三种图每轮 p50 都下降，小型加权图的独立 JVM 中位数回退，p95 增加 50.1%。

同进程对比：每种图运行 3 个 JVM，在同一张图上交替调用新旧算法；每版本预热 8 次、测量 24 次。基线计算器、种子算法和残量核全部从 `f15dab0` 分别重命名编译，避免旧构图共享新算法。基线结果适配增加一个 32 B 记录对象。24 个样本的 p95 为第二大值。

| 场景 | 前/后 p50（ms） | p50 变化 | 前/后 p95（ms） |
| --- | ---: | ---: | ---: |
| 网格 | 1,593.605 / 942.611 | -40.9% | 2,223.206 / 1,484.582 |
| 树形 | 1,770.534 / 896.418 | -49.4% | 2,299.667 / 1,322.434 |
| 梳状网络 | 49.801 / 25.878 | -48.0% | 120.025 / 62.314 |
| 加权需求 | 2.701 / 1.888 | -30.1% | 9.239 / 9.763 |

同进程的前三种图每轮 p50/p95 均下降。小型加权图虽 p50 下降，但 p95 中位数增加 5.7%；两种协议不足以保证小型网络普遍提速。

桌面和原有游戏进程继续运行，存在明显调度和负载波动；最终计时期间没有并行运行 Gradle 测试或 GameTest。JSON 同时保留探索测量、最终测量、全部样本和各轮范围。合成网络重算的耗时不代表完整整合包的 TPS。

## 验证

新增测试验证多个本地供给面、零容量供给面、本地需求与中继过境流量同时存在时，种子流达到最大值并保持容量、流量守恒和最小割证书；另验证连续计算结果的成员独立性。

通道回归覆盖 3,000 个随机物理网络、2,000 个随机有向残量网络、20,000 层链、并行边、回退重路由、限定流量和强制 push/relabel。另完成 20,000 个真实 AE2 对象合成图与独立矩阵 Edmonds–Karp oracle 的对拍，以及无线、多方块、禁止转发、无限模式、重复供给、断开重连和容量变化检查。

两次完整回归各执行 1,294 项测试，均有 1 项可选运行时测试跳过。通道类的全部测试在定向回归和完整回归中通过。将失败用例后续复跑的状态合并后，最新逐项结果为 1,293 通过、1 跳过、0 失败；这不是一次完整执行的结果。每次执行计数见 JSON。

产物 `build/libs/thunderbolt-forge-1.20.1-2.0.0.jar`，SHA256：`d08a39678ac27f90e3a77ef45d3ddb3678ab3102b359b2a550a2f71bcf4ba16e`。

两次完整回归在未修改的合成规划器用例中出现限时或预算相关失败。第一轮为一个 3 秒超时；第二轮为五项失败，包含 1 秒/3 秒超时、100 ms 精化预算耗尽和补料可行性断言失败。相关类或单项随后按原限时和原断言复跑均通过，完整单轮全绿尚未取得。原始失败记录保留在忽略目录，JSON 按每次运行记录计数，不能将逐项复跑结果表述为单轮完整测试通过。
