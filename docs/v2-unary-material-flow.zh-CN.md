# 单原料配方的稀疏流求解

大型共享原料分配图可能超过通用整数模型的宽度限制，随后启发式分配报缺料，即使库存来自一份已知可行分配。对于严格受限的配方子类，可以直接使用整数网络流。

准入条件：每个配方只有一个普通消耗输入，没有副产物、返还物或私有复用；材料依赖无环；同一种材料在所有配方中的输入、输出系数一致。不同材料之间系数可以不同，例如 `3A → 2B → 5C`。

材料作为节点，配方作为边，边流量就是执行次数。对材料余额先减去实际库存及外部供给，再除以该材料的固定系数并向上取整。这保留零散库存，且与原始整数余额约束等价。残量网络可重新分配已占用的原料，为只有单一路线的需求保留库存。

实现使用迭代 Dinic 路径，按残余瓶颈批量增广，不按物品数量循环，也不递归遍历长链。仍消耗同一份工作预算；预算耗尽与数学不可行分别返回。符合条件的组件优先使用此内核，结果继续经过原有完整计划校验。不符合条件的图维持原求解路径。

验证包括独立穷举分配、原始配方执行次数穷举、批量余数、共享库存、5000 层链和多个材料总量超过 long 的情况。64～4096 个输出的大型分配用例同时测试数量 1 与 10^12，验证导出执行次数的 BigInteger 余额及实际库存上限。

真实缺料时，先最大化现有库存的流，再仅向原始天然叶子加入虚拟供应，在同一残量网络继续增广。每个转换都传递一个材料批次单位，因此剩余交付缺口对应最少的新增单位数。原始批量余数决定一个新增单位实际需要补多少物品，最终数量必须通过完整原始配方余额计算，不能直接将虚拟流乘以批量。

对满足准入条件、边界需求固定的组件，所得补料向量不存在逐项更小的可行向量：降低任一非零物理缺口会减少可用的新增批次单位，与已有最大库存流的剩余交付缺口冲突。这不代表不同材料总数、价格或整张任意配方图的全局最优。

虚拟供应的结果与实际库存可行结果分别保存，前者始终是缺料候选。所有组件与固定前缀合并后，需要完整 DAG 余额证明；随后仍在原有预算内重新规划补料后的图。若既有保守配方策略无法重现，复核成功的流候选可以保留。预算不足时仍回退已有保守清单。

缺料验证包括 256 组原始配方执行次数穷举及 Pareto 对照；64～4096 输出、单位与万亿数量、单位与不同比例批量的单单位真实短缺；120 组大型分配及 60 次补料重算。测试同时检查原始天然叶子限制。
