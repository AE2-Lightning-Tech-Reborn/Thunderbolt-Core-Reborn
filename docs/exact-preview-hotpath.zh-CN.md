# 普通计划精确数量检测优化

本轮基于 TB Reborn `alpha` 的 `69e9af1b35b533f4593c122eff7b46a3ee4c37cf`，目标环境为 Minecraft 1.21.1 / NeoForge 21.1.219。生产修改仅涉及 `ExactPlanPreview.needsExact` 及其私有辅助方法。

## 调用位置与语义

`FastCraftingPlanner` 在取得普通计划后调用 `needsExact`，决定是否转入精确诊断路径。原实现对每个配方的主产物、副产物做 BigInteger 乘加并汇总，最终仅比较是否达到 `Sat.SAT`。

新实现先检查汇总数量与执行次数，用原生 long 映射累计非负产出，并在乘法或加法达到阈值时返回。小于阈值的 exact 数量才转换为 long；输入和输出的 exact 字段始终是判定依据，不能使用可能独立截断的 long 投影。零执行次数不产生输出，但输入本身达到阈值仍沿用原来的精确诊断行为。

累加开始前完整检查执行次数。若外部构造的计划含负次数，保留原 BigInteger 计算以支持相消，避免把某个中途的大值误判为最终结果。汇总数量、达到阈值的执行次数、同键主副产物、不同配方的同键产出均保持原有判定。没有改动规划搜索、库存扣取、执行证明、精确报告生成或字节计费。

## 测量方法与结果

真实生产类分别从基线提交与修改后的源码编译，其他依赖保持相同；驱动使用 AEKey 子类，调用实际 `ExactPlanPreview.needsExact`。Java 21.0.12 / Oracle GraalVM，固定 512 MiB 堆，四个独立 JVM 按 A/B/B/A 顺序运行。每个场景预热 1.5 秒，采集 7 个至少 150 ms 的样本，表格报告每版 14 个样本的中位数。每次调用均核对预期的精确/普通判断，四轮签名一致。

`distinct-N` 为 N 个配方，各有一个不同主产物和副产物；`overlap-N` 为 N 个配方的主产物与副产物汇入同一键。每个普通配方执行 1,000 次。分配量来自当前线程分配计数。

| 场景 | 基线 μs/次 | 优化 μs/次 | 耗时变化 | 分配 B/次，基线 → 优化 |
| --- | ---: | ---: | ---: | ---: |
| 空计划 | 0.0265 | 0.0137 | -48.4% | 184 → 0 |
| distinct-1 | 0.1476 | 0.0725 | -50.9% | 1,400 → 352 |
| distinct-32 | 2.3057 | 1.4326 | -37.9% | 15,736 → 3,016 |
| overlap-32 | 1.9330 | 0.7477 | -61.3% | 16,808 → 616 |
| distinct-128 | 10.1160 | 6.0768 | -39.9% | 60,312 → 12,328 |
| overlap-128 | 7.8511 | 2.6167 | -66.7% | 64,424 → 616 |
| distinct-1024 | 90.7720 | 70.6101 | -22.2% | 476,104 → 98,488 |
| overlap-1024 | 64.2776 | 30.0628 | -53.2% | 508,840 → 616 |
| 汇总数量达到阈值 | 0.0225 | 0.0176 | -21.4% | 164 → 96 |
| 单项产出 10^100 | 0.1046 | 0.0367 | -64.9% | 1,168 → 408 |
| 主产物与副产物相加达到阈值 | 0.1706 | 0.0530 | -68.9% | 1,336 → 280 |
| 负执行次数相消兼容分支 | 0.1344 | 0.0528 | -60.7% | 1,152 → 408 |

本组普通计划样本耗时减少约 22%～67%，分配减少约 75%～99.9%；本矩阵未测得回退。这里只测精确数量检测步骤，不包含整条规划、服务器 tick、机器执行或网络 I/O。不能由此推算整体规划或 TPS 增幅；纳秒级小样本受 JVM 编译和系统调度影响，结果用于说明指定场景。

## 正确性验证

新增 6 项测试，包括 10,000 组固定种子的随机计划，与独立完整 BigInteger 汇总 oracle 对照。覆盖阈值前后、乘积溢出、10^100 产出、同键主副产物、容器返回物、跨配方汇总、零次数、不同 long/exact 投影、负次数相消及所有原有汇总守卫。

完整 `./gradlew --offline build` 成功：179 个套件，1,407 项测试，1,402 项通过，0 失败、0 错误，5 项可选兼容测试跳过（ExtendedAE Plus 1 项、NeoEco 3 项、Useless 1 项），与基线的可选依赖缺失范围一致。

以上为本项独立验证；与候选队列、小额 exact 存储优化共同整合后的结果见[组合验收](provider-schedule-optimization.zh-CN.md#组合验收)。
