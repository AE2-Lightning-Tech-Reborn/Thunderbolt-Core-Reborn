# 原版、Lean、最新 Thunderbolt 完整对照

后续 RL 弱缓存已单独优化，见 [ResourceLocation 缓存复测](resource-location-cache.zh-CN.md)。本文保留流体/NBT 版本的完整快照；其中 RL 默认关闭的说明和数字不代表后续版本。

2026-09-19 全量重新测量，包含普通流体直接缓存及 NBT 转换/收集合并。所有性能数字均来自本轮，不拼接旧轮次结果。

## 版本与方法

- 原版对象基线：Thunderbolt `3798e5b0300eddb19706cd9352ba0a29f957048b`，对象优化之前的 AE2 原生实现；仍加载相同的 TB 其余功能，不是彻底移除 TB 的整包。390 个受版本控制文件与 git archive 逐一核对一致。
- Lean：`neoforge/1.21.1` 的 `22d4c0930353b4904a75499f47f25d876e26b2ef`，本轮 fetch 核实远端未变；源码无改动，以 NeoForge 21.1.219 构建，使用默认配置。
- 最新 TB：`experiment/object-reuse-20260919` 的普通流体和 NBT 优化版本；运行时源码及实验 jar 的 SHA-256 见附表。ResourceLocation 构造缓存仍默认关闭。

共同使用 Minecraft 1.21.1、NeoForge 21.1.219、AE2 19.2.17、Temurin 21.0.11+10、arm64。每组各 3 个独立工厂循环 JVM、3 个混合基准 JVM，再另开一个只用于对象大小测量的 JVM，共 18 个计时进程和 3 个大小测量进程。各轮按 BASE→LEAN→OURS、LEAN→OURS→BASE、OURS→BASE→LEAN 顺序轮换执行，无并行争用。大小测量代理不参与计时结果。

沿用已提交的同一外部基准。独立循环 8 轮预热、9 轮测量，每轮 100 万次；混合基准 6 轮预热、7 轮测量，工厂每轮 20 万次、NBT 每轮 5000 次。先取每 JVM 的中位数，再取三个 JVM 中位数。每个结果写入 volatile sink；分配为 ThreadMXBean 当前线程分配量，不等于存量堆占用。
