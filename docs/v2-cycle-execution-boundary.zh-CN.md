# 完整环求解与执行顺序的边界

整数余额满足、存在Petri执行轨迹、当前CPU能够可靠执行，是三个不同条件。将完整非自增环加入优化模型前，需要同时处理运行时的顺序约束。

例如初始A=4、C=4，存在四条配方：

- A+C→2B，执行2次；
- B→A，执行1次；
- A+B→2C，执行3次；
- 2C→T，执行4次。

依次执行上述四组，可以完成4个T。但如果先制作2个T，C就被耗尽，其余三条配方全部阻塞。这个环没有资源自增；只检查最终余额或证明存在一个顺序，仍不能排除错误派发导致的卡住。

当前`FastCraftingPlanner.toAe2Plan`按真实样板汇总`patternTimes`，普通任务未附带Petri轨迹的阶段和重复块。普通批量派发依据当时可用库存提取材料。因此，本轮V2优化保留原有切环路径，不把仅凭存在性轨迹验证的完整环方案接入默认结果。

进一步支持完整环，至少需要将压缩执行轨迹连接到任务派发：记录当前阶段、限制可启动的样板及次数、等待相关产物实际返回，并在保存/恢复时保留状态。还需覆盖原版CPU、批量CPU、多个供应器及模糊输入；否则求解阶段的正确性无法自动延伸到执行阶段。
