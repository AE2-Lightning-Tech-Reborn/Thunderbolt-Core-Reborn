# GTL 上游更新移植（2026-10-08）

目标为 `AE2-Lightning-Tech-Reborn/Thunderbolt-Core-Reborn` 的 `1.20.1_GTL`，
基线为 `7ce573c`。普通 Forge 更新取自 `1.20.1@83fd488`；通用批量派发修复
取自 `main@8acfbca`，按 Minecraft 1.20.1 / Forge 环境适配。

## 移植内容

- 移植发布元数据、JAR/POM 校验、依赖 Release 下载与 12 项 Python 回归。
  Forge 标签支持直接版本号或 `1.20.1-<版本>`；版本类型和更新日志沿用上游发布流程。
- GitHub Packages 地址随当前仓库变化。GTL Maven 包名为
  `com.moakiee.thunderbolt:thunderbolt-reborn-forge-1.20.1-gtl`，避免与普通 Forge
  同版本的不可变产物冲突。JAR 名和模组 ID 沿用已有配置；版本仍为 `2.0.0`。
- 移植 `170d8cb` 的物料 DAG 可行性回放与独立冷启动任务。20 次新配方身份的
  万亿数量规划在独立测试 JVM 中执行，并加入 `check`。
- 提供器可基于已解析的一份实际输入准备批量准入；确认容量后再抽取其余输入。
  准入拒绝和准备异常退还原型输入，最终 offer 遵循能源与容量限制。
- 成功接收部分批量后，空闲提供器可以继续接受普通单件工作。每个物理 CPU
  保留独立 tick 调度器；新 tick 恢复可重试候选，提供器变更使快照失效。
- 添加生产派发回归，覆盖具体替代输入、准备拒绝/异常、低能源、提交异常的
  输入所有权，以及准入作用域隔离和普通派发回退。
- 冷启动验证中补修小图预检：选中的物料 DAG 先用完整余额认证，避免为无环
  可行替代路线加载循环枚举与 SCC 认证。循环候选仍走原有全顺序证明，预算不变。
- DAG 候选生成后立即验证，找到可行路线就停止枚举。修复冷启动时枚举先耗尽
  100 ms 配额、已生成混合路线未获验证而返回缺料的情况；保留原时间、次数、
  工作预算及原配方身份恢复和整图执行证明。
- 恢复保守投影时保留 DAG 全顺序证明：重新核对投影余额、原配方注册身份、
  相同输入与主产物、库存及请求；恢复只增加旁产物时继续使用该证明，避免
  重复循环认证丢失已证明的可行混合路线。新增证明恢复及拒绝错误映射回归。
- 对现有次数向量的保守 DAG 认证前移到执行检查，以真实库存验证当前候选，
  避免冷启动可行性依赖限时路线搜索。
- 恢复证明时保留原计划的物理库存预留，补足 DAG 证明所需的最小量，并逐项
  核对实际库存；避免证明恢复把库存优先的整批预留改成最小净提取量。
- CP-SAT 的短零缺料阶段获得可行解后，固定已证明的零缺料目标并在剩余总预算
  内继续优化执行次数；未完成时保留可行解与部分结果标记，不扩大截止时间。

## GTL 适配

保留 Java 17、Forge 47.1.3、AE2 15.4.10，以及 GTL CPU 让位、独立计算等待、
`thunderbolt$` 访问器命名和 AdvancedAE Forge 反射兼容。
现有物料组件证明缓存和共享种子压缩调度保持当前 GTL 实现。

没有引入 NeoForge 的 Useless 专用适配器。已核对的官方 Forge 1.20.1 API 缺少
该适配器所需的 BigInteger / Smart Doubling 协议，上游 Forge 也已删除相应适配器。
本次采用的是其通用准入与派发生命周期修复。

验证进程的调度优先级，没有改动其他进程或放宽测试阈值。

  0 项失败，1 项因未提供可选 EAEP 实际构件跳过。原有时间断言和算法预算未放宽。

- 默认 `2.0.0` 产物的 JAR、POM、Forge 元数据、JarJar 和 refmap 校验通过；509 个
  生产类均为 Java 17 字节码（major 61），包含新的 `PreparedBatch` API。
  `thunderbolt-forge-1.20.1-2.0.0.jar` 的本地验证产物 SHA-256 为

验证记录、运行夹具、临时目录和构建产物仅保留在本地忽略目录，不加入提交。
