# GTL 频道构图与分配优化（2026-10-05，第二轮）

对比基线 `84a0dc9`。本轮继续减少大型频道图构建和结果读取的分配；不修改规划器、GTL 调度或频道最大流算法。

## 实现

网络发现时同时累计已发现节点的连接端数量和需求节点数量，据此估算残量边容量。内部连接在两个端点各出现一次，对应两条正向边、两条反向边；原版控制器面连接对应一条供给边及其反向边。禁止转发的需求终端计入连接数量但仍不扩展遍历；未知或排除的连接只会使估算偏大。

残量网络的初始分配不超过原有 `6 × 顶点数`，低估时沿用自动扩容。避免预分配明显超过树/深链实际需求的三组边数组，同时不为异常密集或不可达连接提前分配过大的数组。

需求引用列表一次按发现数量分配，省去反复扩容。需求边连续排列，因此获配量可直接从反向残量读取，完整获配等价于正向残量为零；节点流量同样从分裂边的反向残量读取。移除两组需求整数列表、节点原始容量数组和需求节点的重复索引查表。

初版在构图前保存全部连接快照以统计容量。探索复测发现它虽减少分配，却没有稳定提速；最终将计数并入已有 BFS，去掉这组快照引用及额外全图扫描。探索结果单独留档，不用于最终收益结论。

## 测量

最终数据见 [JSON](benchmarks/gtl-channel-optimization-20261005.json)。环境为 Java 17.0.20、Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10；独立 JVM 使用 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。网格、高容量树、20,000 层链分别前后各运行 3 个 JVM，顺序交替；每次预热 3 次、测量 12 次。

最终测量在完整回归和 GameTest 结束后串行执行。计时排除图构建和校验，使用真实 AE2 `GridNode` / `GridConnection` 和生产频道分配代码。原有桌面和游戏进程继续运行，因此时间可能受系统负载影响。12 样本的 nearest-rank p95 等于最大值，堆池峰值合计不是进程 RSS。

| 场景 | 前/后 p50（ms） | 前/后 p95（ms） | 前/后分配（MiB/次） |
| --- | ---: | ---: | ---: |
| 272,650 节点网格 | 865.096 / 975.132 | 1,114.590 / 1,206.361 | 118.697 / 101.208 |
| 226,898 节点树 | 656.515 / 655.807 | 911.072 / 1,274.360 | 95.163 / 76.173 |
| 20,000 层链 | 20.325 / 16.912 | 31.962 / 26.848 | 8.197 / 6.115 |

各行取三个 JVM 各自统计量的中位数。分配量分别减少 14.7%、20.0%、25.4%，全部大网均取得预期频道数量，深链未发生栈溢出。网格 p50 增加 12.7%，树形 p95 增加 39.9%，不能将本轮称为稳定提速。

为减少不同启动与负载时段的干扰，另在同一 JVM、同一图上交替调用新旧计算器：每图 3 个 JVM，各版本预热 8 次、测量 24 次。旧计算器使用旧构图代码和最终残量核；其默认构造容量保持原行为，结果适配另分配一个 32 B 记录对象。此组比较构图与回写开销，不代替完整独立版本对比。

同进程网格 p50 中位数为 708.571 → 702.845 ms（-0.8%），p95 为 767.484 → 805.100 ms（+4.9%）；树为 507.415 → 558.167 ms（+10.0%），p95 为 862.648 → 746.248 ms（-13.5%）。各轮方向不一致，证据支持稳定减少分配，但不足以保证耗时下降。保留两套协议的全部样本和观察到的回退。

## 验证

新增测试验证：从很小的残量数组自动扩容后，在限定流量和强制 push/relabel 两种路径中保持容量与节点守恒；加权设备只获配 8/12 时回写 8、不给予完整频道；没有需求的网络返回空流量。

复用现有独立最大流 oracle、并行连接、无线限流、物理连接、多方块共享需求、禁止转发、无限模式、重复供给、断开重连与深链检查。另复测致密树、原版控制器面、加权设备、梳形链和超额需求树。

完整单元测试共 1,292 项：1,291 通过、1 项可选运行时测试跳过、0 失败。冷启动 CP-SAT、发布 Jar/refmap 校验和强制 `gtlCompat=always` 的 10 项隔离 Forge/AE2 GameTest 通过。GameTest 的受控合成检查不构成高容量工厂整合包测试；完整 GTLCore/GTCEu/AE2LT 包的 TPS 仍未测量。
