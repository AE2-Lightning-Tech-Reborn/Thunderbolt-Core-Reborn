# 补料精修质量回归修复（2026-10-09）

[本轮全局测试](gtl-global-test-20261009.zh-CN.md)在 `MaterialDagBudgetTest.refinementKeepsTheSmallerSupplementAndItStillReplansWithMinimalSearch` 首次失败：期望 `M2 < 6`，实际返回 `M2=6`。生产精修允许在累计 100 ms 时限耗尽后保留已验证补料，测试却要求可选精修每次都完成改进。本轮修复这项测试契约，没有修改生产规划代码或预算。

## 质量与时限分别验证

质量回归从真实配方认证的 `M2=6` 执行向量出发，用现有 `MaterialDagOrders` 完整编译 DAG 候选，再运行实际 `MissingRefinement`。该组件验证使用有限工作量预算，不为顶层质量精修安装 100 ms 可选发现时限；各候选仍调用真实规划器，并还原原始配方身份。接受的候选必须通过证书、精确资源平衡和独立的所有可执行顺序回放。

质量断言加强为精确 `{M2=2}`，并保留补料后以最小搜索预算重新规划可行的要求。此组件测试验证配方与精修能力，不承诺生产调用在任意调度条件下都能于 100 ms 内完成优化。

生产默认入口另有集成测试：结果必须只报告 M2 缺料、数量不超过已认证基线 6，且库存与物料平衡正确，补料后仍可执行，补料探测不超过原有上限。已有强制精修过期测试继续要求精确 `M2=6`；新增接受第一次改进后立即过期的测试，必须保留精确 `M2=5`。预算比例、共享累计上限和外部取消测试继续保留。

## 修复验证

使用相同观察器在原始和修改后的 JUnit 方法进入精修时暂停 110 ms：旧测试 5/5 失败，修改后 5/5 通过，每次均确认暂停触发。诊断夹具从修复前提交提取原测试，仅在独立 JVM 类路径中覆盖该测试类，生产代码相同。观察器自身也有开销，该对照证明修复后的质量回归能承受此暂停，不代表已经确定首次全量失败的具体 GC、JIT 或调度事件。

Java 17、Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10。精简证据、原始测试与修订测试哈希、受控暂停夹具及本轮发布产物哈希见 [gtl-refinement-quality-fix-20261009.json](benchmarks/gtl-refinement-quality-fix-20261009.json)。可使用 `./gradlew test --tests '*MaterialDagBudgetTest'` 或 `./gradlew build` 复验。
