# GTL 通道种子算法临时空间优化（2026-10-05 至 10-06，第四轮）

对比基线 `08b3e13`。本轮按算法阶段复用临时数组，减少大图重算时的分配，保留上一轮 BFS 节点编号顺序。

## 实现

种子算法的父节点数组用于森林发现和供需汇总；这两个阶段结束后，将它清空并复用为子节点链表头。父边仍保留父子关系，只有构建链表时读取一次父边反向端点。避免在森林发现和供需汇总的热循环中增加间接索引。

供给汇总数组在某个节点完成向父节点的贡献后，该节点的槽位不再用于汇总，将它复用为该节点的有符号流量平衡。反向遍历保证所有子节点已完成，父节点尚未处理，数组复用不会覆盖仍需使用的供给数据。

需求汇总直接遍历超级汇点的反向边；回放时读取节点输出邻接表开头的需求边，省去需求边索引数组和初始化扫描。它沿用现有前提：节点分裂边、成对物理边先加入，供给和需求边后加入。回放支持同节点多个需求边及零容量需求边；生产构图通常每个需求节点只有一条需求边。

边界队列及随后使用的兄弟链接复用当前残量网络已有的 BFS 队列。种子完成后，残量树形补流和 push/relabel 才使用同一队列，各阶段只访问自己写入的有效范围。每次计算仍拥有独立残量网络，没有全局缓存或跨次复用。

没有供给边或需求边时，种子在分配数组前返回零。供需汇总没有匹配流量时，跳过链表构造和零流量回放，由残量算法从原图继续精确补流。

种子临时空间从每节点 52 字节降至 32 字节，减少四个数组及其头部，即约 `20 × 节点数 + 64` 字节。残量网络原有 BFS 队列容量保持原值；生产构图、结果集合和节点编号保持上一轮实现。

## 测量

完整数据见 [JSON](benchmarks/gtl-channel-workspace-20261005.json)。环境为 Java 17.0.20、Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10，JVM 参数为 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。

真实 AE2 对象测量分两种协议：独立 JVM 前后各运行 3 次，逐轮交换顺序；同进程每图运行 3 个 JVM，在同一图上逐次交替新旧版本。基线计算器、种子和残量核全部从 `08b3e13` 独立编译，同进程基线结果适配多分配一个 32 B 记录对象。计时排除图创建和验证，全部结果均检查流量和容量。

大图独立 JVM 预热 8 次、测量 12 次，同进程预热 8 次、测量 24 次。梳状网络预热 64 次、测量 24 次；小型加权网络预热 200 次、测量 100 次，降低短时间运行中 JIT 编译的影响。统计量取三个 JVM 各自统计量的中位数，p95 使用 nearest rank；12 样本的 p95 为最大值。

耗时不能作普遍提速结论。梳状网络在三个独立 JVM 中都回退，p50 中位数增加 11.695 ms，p95 中位数增加 60.872 ms；同进程 p50 接近持平，但其中一轮新版本 p95 达到 280.755 ms。网格在独立 JVM 中下降较大，同进程仅下降 3.7%，且同进程 p95 增加 15.9%。树形的两种协议均有 p50 收益，小型加权图则没有一致方向。完整样本和每轮范围均保留，不能将协议间差异全部归因于环境噪声。

梳状网络的三轮 p50 变化约为 -43.3%、+23.6%、+125.3%，增加预热后仍有两轮回退。此次优化以减少临时分配为收益，保留精确最大流；对梳状网络的耗时风险尚未消除，不能宣称这轮全面优化了延迟。

探索阶段曾尝试省去父节点数组，并在供需汇总中从父边推导父节点。测量出现树形和梳状网络回退，最终改为在该数组完成工作后再复用它。探索记录单独保留，包含初期预热不足的小型图结果；不能用它替代最终协议。

随后还尝试在供需汇总完成时把父节点编号暂存到闲置队列，再在子节点链表阶段读取，以省去一次父边反向端点查询。同进程三轮、四种图的测量没有稳定收益，最终未采用；候选单独编译，生产源代码保持已经验证和计时的版本。

所有最终计时在完整验证结束后串行执行，未与 Gradle 或 GameTest 重叠。原有桌面和游戏进程继续运行，仍有调度、GC 和系统负载波动。合成通道重算的结果不等于整合包 TPS。

## 验证

新增测试验证多个本地需求边、零容量需求边与向下游转发同时存在时，种子满足容量、守恒和最小割证书；另在有限种子流后分别运行树形补流和强制 push/relabel，验证兄弟链接不会污染后续 BFS 队列。

定向通道回归覆盖 3,000 个随机物理网络、2,000 个随机有向残量网络、20,000 层链、并行连接、重路由、重复供给、溢出和容量限制。完整单轮测试 1,296 项：1,295 通过、1 项因未提供可选 EAEP 运行时而跳过、0 失败。冷启动 CP-SAT、发布 Jar/refmap 校验和强制 GTL 兼容模式下的 10 项隔离 Forge/AE2 GameTest 通过。

另外，20,000 个真实 AE2 对象随机图通过独立矩阵 Edmonds–Karp oracle 对拍；并行路由、共享瓶颈、无线、多方块、禁止转发、无限模式、重复供给、断开重连和容量变化检查均通过。
