# GTL CP-SAT 原生初始化验证（2026-10-06）

适用环境：Minecraft 1.20.1、Forge 47.1.3、Java 17、Windows x64；分支 `1.20.1_GTL`。

上一轮留下的 `new_Domain__SWIG_2(long,long)` 原生绑定错误已定位。固定版本 OR-Tools 9.15.6755 的 `Loader.loadNativeLibraries()` 会吞掉原生文件解压期间的 `IOException` 并正常返回，旧桥接层因此发布了实际不可用的运行时。缺少原生绑定的异常随后才出现在真实规划中。

相同 Java/native JAR 的父加载器与隔离子加载器探针，使用空间不足的系统临时目录时均为 `Loader.loaded=false`，构造原生 Domain 失败；改用有空间的临时目录时均成功。该证据支持解压失败，而不是之前尚未证实的 DLL 版本冲突。系统临时目录中存在约 10 GiB 原生副本；本次只清理了超过一小时、逐文件匹配固定 JAR 哈希且未被占用的 29 份完整副本，约 2060 MiB。

桥接层初始化现在先创建一个固定变量，并以单线程完成真实 CP-SAT 求解，确认 JNI Domain 与求解器同时可用后才标记初始化完成。同一桥接加载器只执行一次该检查；失败继续由现有隔离运行时记录，保持不可用状态。

新增两项独立 JVM 回归分别检查正常初始化，以及原生解压目录不可用时拒绝发布运行时。故障夹具在 JVM 启动时传入临时目录，并为 JNA 提供单独的有效目录，防止 JVM 对临时目录的缓存掩盖故障。同一故障回归在 `71d13c1` 上失败（误报可用），本次候选通过。

补货取消/截止时间测试改为只观察实际检查点的直接调用者，并在没有可选截止时间时立即返回，避免逐检查点构造完整调用栈干扰原有 100 ms 时间片。产品预算没有调整。上一轮终端回退的原子预算断言在 `e603fc3` 与 `71d13c1` 的独立 JVM 中均连续通过 5 次，本次没有修改终端回退生产逻辑。

完整验证通过：常规测试 **1319 项，1318 通过、1 项可选 EAEP 集成跳过、0 失败、0 错误**；独立 JVM 的 CP-SAT 冷启动回归 **1 项通过**；发行 Jar/refmap 检查通过。Forge 47.1.3、Java 17、真实 AE2 且强制 `gtlCompat=always` 的 **10 项 GameTest 全部通过**。

验证期间保留两次先前尝试：第一批因工作盘被原生副本占满，测试输出连接中断；释放空间后，171 项定向测试有 170 项通过，只有新增故障夹具失败，原因是运行中修改临时目录被 JVM 缓存掩盖。修正夹具后，上述完整验证及基线对照均通过。本次没有以扩大时间预算消除失败，也没有重新宣称上一轮普通链和会话场景的性能提升。
