# CPU 刷新与样板委托解析优化

本报告记录 Minecraft 1.21.1 的 TB Reborn `main` 开发阶段结果，基线为 `9c95dd4`。当时保留工作区已有的规划器改动，仅调整两个运行时热点。后续整合到 `alpha` 的验证见[第二轮报告](runtime-hotpath-followup.zh-CN.md#alpha-整合验证)。

## 行为与边界

- `DynamicCraftingCpuClusterIndex.refresh` 由合成服务每 tick 调用。收集当前集群时同步检查新实例；没有新实例且去重后的数量相同，即可证明集群集合未变化，跳过独立的集合比较、移除扫描和重复写入。仍然每次重新解析全部 provider，因此不依赖节点事件来发现替换、启动或失活。发生变化时使用 identity 集合求交，保持对外集合视图与新增回调语义。
- `CraftingPatternDelegates` 对普通样板和单层包装直接返回。多层包装仍使用 identity 集合检测循环，每个委托方法最多调用一次；执行目标与 provider 查找目标继续分开解析。没有增加跨 tick 缓存。

## 基准方法

`scripts/runtime-hotpath-benchmark/run.py` 分别编译基线与优化后的两个真实生产类，使用相同依赖和测试驱动，按 A/B/B/A 启动四个独立 JVM。每个场景预热 1 秒，再采集 7 个至少 100 ms 的样本；下表为每个版本 14 个样本的中位数。运行环境为 Java 21.0.12 / GraalVM，固定 512 MiB 堆。

委托解析的一次操作包含一次执行目标解析和一次 provider 目标解析；混合场景在 32 个样板间轮换，包装深度依次为 0、1、2。CPU 场景每次刷新整个索引，变化场景在 1,024 个 provider 中轮换替换一个集群实例。测试驱动使用代理样板和简单 provider，未测量真实世界中的机器逻辑、网络 I/O 或服务端 TPS。

| 场景 | 基线 ns/操作 | 优化 ns/操作 | 耗时变化 | 分配 B/操作，基线 → 优化 |
| --- | ---: | ---: | ---: | ---: |
| 混合样板解析 | 9.328 | 5.425 | -41.8% | 357 → 170 |
| 无包装样板 | 1.055 | 1.165 | +10.5% | 0 → 0 |
| 单层包装 | 12.042 | 1.748 | -85.5% | 544 → 0 |
| 两层包装 | 14.791 | 14.101 | -4.7% | 544 → 544 |
| 八层包装 | 49.726 | 45.772 | -8.0% | 544 → 544 |
| 空 CPU 索引 | 16.362 | 15.976 | -2.4% | 0 → 0 |
| 1 个稳定集群 | 66.044 | 30.613 | -53.6% | 0 → 0 |
| 64 个稳定集群 | 1,071.004 | 474.216 | -55.7% | 0 → 0 |
| 1,024 个稳定集群 | 16,952.789 | 8,076.479 | -52.4% | 0 → 0 |
| 4,096 个稳定集群 | 76,691.999 | 31,550.651 | -58.9% | 0 → 0 |
| 1,024 个集群，每次替换一个 | 15,752.289 | 16,244.857 | +3.1% | 16.0 → 20.2 |

主要收益在稳定集群与单层包装。无包装路径原本已被 JIT 消除分配，本轮仅有约 0.11 ns 的绝对耗时增加；持续变化场景测得约 0.49 μs 的增加，保留为性能边界，不宣称全场景提速。小幅耗时和变化路径分配量受 JVM 编译状态影响，本表只说明这组局部测量。

完整中位数见 `docs/benchmarks/runtime-hotpaths-20261022.json`。复测命令：

```sh
python3 scripts/runtime-hotpath-benchmark/run.py --baseline-ref 9c95dd4
```

脚本在 `build/runtime-hotpath-benchmark/` 保存源文件哈希、JVM 参数、分次原始样本与汇总。可用 `--warmup-ms` 和 `--sample-ms` 延长测量；`--skip-build` 仅适用于已导出依赖路径的工作区。

## 正确性验证

回归覆盖 1,024 层委托、前缀后的循环、自委托、空委托、每节点只解析一次、集群共享、同值不同实例替换、最后一个 provider 移除、稳定刷新中的动态激活，以及 1,000 轮随机变化与独立 identity 列表模型对照。

最终执行 `./gradlew --offline cleanTest build` 成功：111 个测试套件、853 项测试，0 失败、0 错误、0 跳过。其中上述两个类的回归用例共 12 项。完整构建包含工作区已有规划器改动；本次提交不包含那些已有改动。
