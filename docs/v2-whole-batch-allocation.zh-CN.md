# 多原料备选路线的整批分配

原有宽图审计包含 80 张有已知可行库存分配的图：8、16、32、64 个需求产物，每个产物有三条双原料路线，共享 16 种原料，请求量分别为 1 和 10¹²。原 V2 解出 52 张，另外 28 张提前触及稠密矩阵容量或整数求解工作量限制，没有耗尽 3 秒时间预算。

新增 `WholeBatchAllocation` 在单输入网络流、公共输入提取均不适用时，尝试普通浅层组件的整批路线选择：

- 每种产物选择一条路线完成所需批次；候选路线的产出批量必须相同，输入必须是天然原料，没有副产物、返还物或私有种子。
- 重复输入槽累加，先扣除同组件的原料直接需求，并计入外部供应。按每种原料的实际整批消耗公约数缩放，用整数除法向下取整库存；不逐件展开请求量。
- 每轮从剩余路线计算各原料必需量及最大可能消耗。库存上界排除不可能的路线；总消耗守恒且库存恰好用尽时，还使用每种原料的下界。
- 优先分支候选少、库存约束紧的产物，再根据原料余量排序路线。浮点数只影响搜索顺序，证书使用原始 BigInteger 数量复核，并经过现有完整规划校验。
- 整批搜索无解或超预算只返回“没有候选”，不证明真实问题无解。同一需求必须拆给不同路线时，仍交回原整数求解器。

该快路最多尝试 128 个产物组、每组 16 条路线、16,384 个消耗单元，另有 1,500,000 单位局部工作量上限，并消耗原有共享工作预算和取消期限。这些条件只限制是否尝试此快路，不是整个 V2 的配方数量上限；没有提高原有稠密矩阵和整数搜索预算。

验证结果：80/80 图均可行，原有 28 张全部恢复；16 个移除一个物理原料单位的对照均保持缺料，补齐报告原料后重新规划可行。600 组独立穷举验证覆盖批量取整、多输入槽和不同库存，另测试拆分才能可行、外部供应、原料直接需求、万亿数量的一单位短缺、准入排除和预算耗尽。43,000 张既有小图的可行性、补料、路线次数和库存使用均与修改前一致；所有初始计划及 14,798 个补料后的计划通过独立逐步执行与任意可执行顺序复核。

本机 3 秒期限复测，80 张图最大约 38 ms、P95 约 5.3 ms。该结果只适用于本次语料和环境，不意味着一般组合分配问题都有多项式时间保证。

## CP-SAT 对照与入口限制

CP-SAT 适配层原先限制本次目标展开后的候选配方不超过 192、物料不超过 256。这不是内核限制。64 产物的审计图有 193 条配方，原先直接返回 `UNSUPPORTED`。

按要求移除了这两个入口限制，保留时间预算、数值安全及执行验证。相同 80 张图在 3 秒调用期限下解出 78 张，剩余两张返回 `UNKNOWN`，不能视为无解；对应原来的 28 张反例解出 26 张。原生求解器按既有策略使用剩余时间的 75%，给结果验证留出时间。

去掉入口上限后，1,000 配方链及约 1,000 配方宽图可以直接求解；10,000 条相同输入输出的备选配方也可以求解，但后者容易被预处理化简，不代表所有万配方图。1,000 配方链已加入回归测试。

另外生成有已知可行库存的随机双原料组合，993 条配方、32 个中间产物约 195 ms 解出；9,985 条配方、64 个中间产物约 1.20 秒解出。两者共享 16 种原料，目标请求量为 1，不是相同配方重复填充规模的测试。将后一张图的库存及请求量同比放大到 10¹² 后，约 2.64 秒解出，仍在 3 秒调用期限内。

当前适配层仍有五张 `配方数 × 物料数` 的稠密 long 矩阵。万配方且万物料的图，仅矩阵就约 4 GB，在 768 MB 测试堆中于编译阶段耗尽内存。删除入口上限不解决这个表示问题；需要另行改为稀疏表示，而不能把内存耗尽解释为 CP-SAT 数学求解失败。此改动没有更改矩阵表示，也没有加入图拆分。
