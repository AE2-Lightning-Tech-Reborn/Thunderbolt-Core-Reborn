# 小额 BigInteger 存储接口优化（2026-10-22）

基于 Thunderbolt Core Reborn `alpha` 的 `69e9af1b35b533f4593c122eff7b46a3ee4c37cf`。
本次仅在 `IndexedStorage.insertExact/extractExact` 增加 13 行快路径，复用现有整数记账。
最终局部基准中，小额 exact 引擎耗时下降 65.85%～91.95%，完整存储接口下降 36.46%～47.84%。
这是离线 JVM 存取测试，不能换算服务器 TPS；旧 long 接口在混合矩阵中有约 7% 的回退，详见下文。

## 实现与边界

之前即使请求只有 4096 个物品，也会构造当前数量、下次数量、差值、类型总量和投影等多个 BigInteger。
现在仅在已启用任意精度、`exactPathPossible == false` 且请求不超过 `Long.MAX_VALUE` 时，转入现有 `insert/extract`。
完整满足的请求直接返回调用者提供的不可变 BigInteger；部分提取仍返回实际接受数量。

`exactPathPossible == false` 表示没有宽数值账本，且每种类型的 126 位总量高字都小于 `Long.MAX_VALUE`。
单个 long 请求最多进一位，因此当前转账不会越过 126 位边界；整数路径会在高字到达边界时置位，后续调用自动回退。
已有宽数值或逼近边界时，仍使用原来的任意精度路径，包括 16384 位上限。
守卫覆盖整个存储对象，因此某一类型触达宽数值后，其他类型也保守回退，直到重载重新计算边界状态。

存档格式、总量计算公式、旧 long 接口的方法体、模拟/执行区别均保持原有实现。
本次不涉及批处理候选队列，便于与并行的 alpha 优化分别验证和集成。

- 新增 4 项测试：63 位进位/借位、键删除与 ID 复用、126 位边界切换、16384 位上限、模拟不改账、零请求和参数/启用状态校验。
- 现有独立守恒 oracle：4 个种子共 100 万次混合操作，3 个元件、1024 个键、372 次重载。

## 性能方法与完整矩阵

GraalVM Java 21.0.12，512 MiB 固定堆。基线/优化分别编译真实生产类，使用相同依赖和测试夹具，
按 A/B/B/A 启动 4 个独立 JVM。每场景每 JVM 预热 1 秒，再采样 7 × 150 ms；表中是每实现 14 个样本中位数。
每个操作是一组“存入 + 取出”。计时区外校验返回数量、完整数量快照以及模拟操作的版本不变。
场景覆盖单键和 1024 个带组件键：4096 数量、Long.MAX_VALUE 数量、模拟、完整元件接口、旧 long 接口、101 位十进制库存。

| 场景 | 基线 ns/组 | 优化 ns/组 | 耗时变化 | 分配 B/组 |
| --- | ---: | ---: | ---: | ---: |
| `engine_small_1` | 109.00 | 8.77 | -91.95% | 976.00 → 0.00 |
| `engine_long_sized_1` | 237.74 | 8.46 | -96.44% | 1872.00 → 0.00 |
| `engine_simulate_1` | 21.47 | 4.87 | -77.33% | 256.00 → 0.00 |
| `inventory_small_1` | 253.71 | 132.33 | -47.84% | 1552.00 → 592.00 |
| `engine_legacy_1` | 7.14 | 7.63 | +6.94% | 0.00 → 0.00 |
| `engine_wide_1` | 221.55 | 193.18 | -12.80% | 1360.00 → 1200.00 |
| `engine_small_1024` | 218.25 | 74.52 | -65.85% | 1047.85 → 71.85 |
| `engine_long_sized_1024` | 324.30 | 74.22 | -77.11% | 2079.85 → 71.85 |
| `engine_simulate_1024` | 96.98 | 66.01 | -31.94% | 327.85 → 71.85 |
| `inventory_small_1024` | 339.58 | 215.78 | -36.46% | 1623.85 → 663.85 |
| `engine_legacy_1024` | 65.17 | 70.07 | +7.52% | 71.85 → 71.85 |
| `engine_wide_1024` | 481.20 | 456.28 | -5.18% | 1720.36 → 1560.58 |

完整元件接口仍包含字节摘要更新，因此单键分配从 1552 B/组降至 592 B/组，而引擎单键小额路径从 976 B/组降至 0。
多键测试仍包含组件键查找的分配；不能把单键的零分配推广到所有调用。

旧 long 接口的混合矩阵回退必须保留：最终单键 +6.94%、1024 键 +7.52%；首轮 1024 键为 +7.66%。
对 1024 键另做独立场景、3 秒预热和 7 × 300 ms 的 ABBA 复测，结果为 -7.01%（70.49 → 65.55 ns/组）。
这些数据说明结果依赖场景顺序和 JVM 编译状态，不能据此承诺所有工作负载均无回退，也不把旧接口或宽数值场景列为稳定收益。
本次接受的是小额 exact 存取明确减少中间对象，并在两轮完整矩阵中获得方向一致的大幅改善。

[机器可读结果](benchmarks/small-exact-transfers-20261022.json)保留最终矩阵、逐 JVM 中位数、独立复测、首轮矩阵及源码/夹具哈希。
首轮之后仅给夹具增加了单场景筛选参数，最终矩阵和独立复测均使用交付的夹具版本；生产代码未改变。
原始逐样本结果位于本地 `build/small-exact-transfer-benchmark/`。

## 复现

在 Java 21 环境下运行：

```sh
./gradlew --offline -I scripts/benchmarks/cell-stress.init.gradle cleanTest build
python3 scripts/small-exact-transfer-benchmark/run.py --baseline-ref 69e9af1
python3 scripts/small-exact-transfer-benchmark/run.py --baseline-ref 69e9af1 \
  --skip-build --scenario engine_legacy_1024 --warmup-ms 3000 --sample-ms 300
```

脚本首次运行会导出完整测试/编译类路径，并将来源哈希、JVM 参数和所有样本写入构建目录。
请避免同时运行其他重型测试或基准。
