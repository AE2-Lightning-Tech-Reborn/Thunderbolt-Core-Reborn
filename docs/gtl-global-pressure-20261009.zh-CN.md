## 首轮失败与独立诊断

`ExternalPlannerBoundaryCompatibilityTest` 的两个案例超过原有 1000 ms 墙钟限制；随后 `boundary-summary` 因只完成 35/37 个案例而失败。共 3 项失败，对应两个超时与一项汇总失败。

- `quantity/craftable-primary-no-variant-stock/1`：org.opentest4j.AssertionFailedError: execution timed out after 1000 ms；测试总耗时 1.147 s。
- `quantity/fuzzy-leaf-white-stock/1`：org.opentest4j.AssertionFailedError: execution timed out after 1000 ms；测试总耗时 1.237 s。
- `boundary-summary`：org.opentest4j.AssertionFailedError: every imported case must execute ==> expected: <37> but was: <35>；测试总耗时 0.001 s。

两个超时快照分别停在 `CraftPlannerV2.buildDagRoot` 和 `PlanningSession.compileReachableGraph`（`Map.copyOf`）。首轮没有逐阶段计时或 JFR，不能据此确认 GC、JIT、线程调度或算法本身是哪一项原因，也不能把全量测试记为通过。

全部重型验证结束后，在 5 个独立 JVM 中执行原测试工厂，保留 37 个案例、汇总断言及每个案例的 1 秒限制：**190/190 通过，0 失败**。回放案例中记录的最大总耗时为 227.507 ms（包含超时包装开销）。这说明独立回放未复现首轮失败，不能消除首轮失败，也没有证明其具体触发原因。

## 验证规模与正确性

环境为 Java 17 / Minecraft 1.20.1 / Forge 47.1.3 / AE2 15.4.10。全量测试强制执行；重型 Java 验证顺序运行，不停止其他用户进程。压力 JVM 使用 G1、256 MiB 初始堆、2 GiB 最大堆、1 MiB 栈和 4 个可用处理器。普通大图夹具另设 15 秒外层截止，内部生产预算保持原值。

本轮使用 78 个压力 JVM，另加 5 个诊断 JVM。普通规划、频道、存储、CP-SAT 循环和并发均恢复 3 个独立 JVM 重复；批量库存使用 3 个固定随机种子。结果验收同时检查退出码、超时、场景完整性、状态与回放失败；频道进程即使返回 0，出现 `STACK_OVERFLOW` 也判失败。
