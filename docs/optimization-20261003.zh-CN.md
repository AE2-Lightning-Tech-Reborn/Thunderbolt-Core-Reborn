# 2026-10-03 Forge 1.20.1 优化

## 实现与来源

- 移植上游 `e9d2f50` 的精确存储截断数组恢复，保留项目 LGPL 许可证及原有署名。
- 2026-10-04 已同步上游 `1.20.1@28a1f25` 的执行次数优先优化器，替代此前 250 ms 的简化资源优化策略。当前默认会话时间上限为 2.8 s，500 ms 没有至少 1% 执行次数收益时停止；预留导出时间并遵守外层期限。保留 JVM 属性 `thunderbolt.maxConsumptionOptimizationNanos` 调整上限。
- 使用可执行性传播、成本下界剪枝、全局策略及局部配方重路由；不再按整图规模关闭探测，而按候选局部图收费，共享最多 32 次探测和工作量预算。执行次数优先，资源只在相同执行次数时作为取舍；不增加既有库存提取或改变有状态配方次数。停止只保留已验证计划，不构成不可行或全局最优证明。
- 不可变配方索引 `IndexCache` 按计算会话缓存，匹配图实例和目标，取消时不发布半成品；数量、库存限制及传播状态逐次重建，不跨候选复用。
- `PlannerTopology` 负责迭代 SCC 与稳定拓扑排序；`OptionalPlanningStages` 负责核心规划后的恢复与优化，保留 V2 的公开接口。
- 普通批量输入槽复用本地拥有的解析结果；传给提供者的输入仍为独立副本。缺少目标时延迟创建模板副本，普通输出路径避免创建共享输出映射。
- 显式登记 Mixin 注解处理器的 refmap 与映射文件为编译输出，开启构建缓存。`verifyReleaseJar` 校验发布 JAR 的唯一 refmap、生成内容一致性、Mixin 配置、清单与 JarJar 元数据。配置缓存仍关闭。

## 本机基准

Java 17.0.20，优化前后在独立 JVM 中执行。每个场景预热 20 轮，测量 20 轮；耗时使用 `System.nanoTime`，分配量来自 ThreadMXBean。测试过程校验可行性、示例最优用料、模板所有权和退款后库存。

以下是 2026-10-03 简化优化器的历史结果，不代表 2026-10-04 同步后的性能。基线是当时改动前工作区的编译产物，消费优化器恢复为当时 HEAD 实现，不是整个上游版本的性能对比。原始历史结果与关键源码哈希见 `benchmarks/optimization-20261003.json`。历史 Useless 行使用模拟协议，不能视为 Forge 发行版性能收益；对应实现、测试和场景现已移除。

## 验证

回归验证包括精确数量持久化往返、可选 API 签名与异常、随机配方执行次数优先及库存边界、取消后缓存恢复、宽图局部探测、共享种子派发、部分派发与退款。发布包还需通过 `verifyReleaseJar`。



## 压测审计修复
