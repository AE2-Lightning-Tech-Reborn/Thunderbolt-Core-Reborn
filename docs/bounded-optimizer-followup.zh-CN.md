# 有界混合配方与 CP-SAT 小图恢复

本文记录此前本地优化。后续上游 `5ce6adf` 同步、库存策略、`COMPLETE` 跳过条件及游戏验证见 [上游库存感知更新](stock-aware-upstream-update-20261004.zh-CN.md)；下文旧测试数量和“尚未游戏验证”不代表当前状态。

## 避免重复优化

双配方返回明确的 `COMPLETE`、`EXHAUSTED`、`UNSUPPORTED` 状态，计划与状态同时返回。普通原料域完成精确搜索且未使用目标库存时跳过通用优化器，避免重复建立索引；预算耗尽或不支持不当作最优证明。使用目标库存时仍保留通用阶段，因为它可能利用批次余量减少目标库存提取。

## 多配方混合

新增三至六种普通目标配方的有限整数搜索，逐项限制既有原料提取，执行次数优先、相同次数比较原料总提取。最多 64 次总执行、32 输入槽、8 种原料，工作量上限 16384，费用从会话共享预算扣除。搜索耗尽保留已独立校验的候选，但状态保持 `EXHAUSTED`；大数量可以是压缩批次，执行次数过大则回退通用方案。不支持副产物、有状态输入或中间配方链。

## CP-SAT 偶发预算耗尽

修改前已知死锁替代路线重复 32 次，首个冷请求仍需要额外种子且标记预算耗尽，另 31 次找到完整路线。所有返回结果通过独立小型 Petri 网可执行性检查：复现的是有限预算下未找到更佳路线，不是已返回计划的材料平衡错误。

在 CP-SAT 昂贵原生块细化前增加小型非增长图恢复，复用现有 `SmallConservativeSearch` 的精确及全执行顺序证书。最多 256 状态，并从同一 verifier 节点/工作预算扣费；外层期限和用户取消仍传播。

初版固定 10ms 预检在全量测试中通过，却在独立 JVM 首个请求再次耗尽；该失败已保留，不以暖启动复跑代替修复。最终预检分配为 `min(100ms, 剩余细化时间 / 2)`，给原生后备路径保留至少一半剩余时间，总细化预算仍为默认 250ms，且整个阶段按实际用时扣除。预检耗尽后继续使用剩余原生细化预算，不将未知结果学习为排除约束。原生初次求解另有原有预算，因此一次完整请求的墙钟时间不等同于 250ms。

新增 `cpSatColdRefinementTest`，仅在独立测试 JVM 中运行新会话替代路线检查，并纳入 `check`；普通全量套件不能再通过提前加载规划器/证书类掩盖这一类冷启动回归。

## 测试夹具稳定性

最终全量运行还暴露三个参考能力分类测试的 50ms 线程调度误超时。这些夹具只返回固定计划或抛出固定异常，却需要为检查、规划及补料创建多个新线程；不应以此测量规划性能。分类夹具改用 2s 截止时间，专用合作/非合作超时测试仍使用 50ms，并单独验证共享截止时间及补料新截止时间；生产规划器和参考执行器实现未因此改变。失败日志与 XML 保留在本地验证目录，不以删除断言或跳过失败测试处理。

这些机制不保证任意整合包图全局最优；支持范围外及资源/时间耗尽时仍可能保留原有缺料或非最优计划。测试和性能数据不能代替游戏内合成提交、多方块执行及实际 TPS 验证。

## 最终验证（2026-10-04）

- Java 17 / Minecraft 1.20.1 / Forge 47.1.3 / AE2 15.4.10；`build optimizationBenchmark` 通过，发布包 refmap、Mixin 配置及 JarJar 校验通过。
- 全量 930 项：929 通过、0 失败、1 个需可选 EAEP 运行时的测试跳过；独立压力 16 项全部通过，含真实 EAEP 1.6.3 协议测试，因此该集成并非未验证。
- 多配方新增 9 项：400 组三/四配方独立穷举、五/六配方、共享稀缺原料、万亿缩放、耗尽保留候选、目标库存不误跳过通用优化器及完成状态不构建重复索引。
- CP-SAT 独立审计：32 个新会话（包含新 JVM 的首个冷请求），缺料及预算耗尽由各 1 次变为各 0 次；全部返回计划通过独立 Petri 可执行性检查。`check` 另运行独立 JVM 冷启动回归，并补测三个独立 JVM（各 8 个新会话）全部通过，不宣称 32 次都是 32 个独立进程。
- 原有压力结果保持：3000 组材料平衡无错误，4000 次并发规划无跨会话库存污染，2000 层链、6000 次发信器切换、10 万次精确存储操作通过；双配方反例仍为 4 次执行/30 原料，不增库存且可减少次数的遗漏为 0。
