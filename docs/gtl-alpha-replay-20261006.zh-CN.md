# Forge 1.20.1_GTL 规划器分配优化（2026-10-06）

本轮在 `ca182d3` 基础上移植上游 `alpha` 分支的版本无关优化提交 `49b5991`。已检查的上游 `1.20.1_GTL` 与通用 `1.20.1` 分支没有新的待移植提交；这里的优化来源是 Alpha，目标仍为 Forge 1.20.1_GTL / Java 17。

此外，针对验证中暴露的宽图材料供给超时，本轮加入本地算法优化：只在一次独立组件求解组合内保存上一个成功整数解。每个新组件重新检查变量域和完整数值约束，包含当前库存与外部供需偏移；检查使用精确长整数，溢出时使用 BigInteger，并消耗共享工作预算、响应取消。约束不满足时正常求解，不缓存失败或不可行结论。组合向量仍由真实库存和材料 DAG 完整重放认证，因此局部库存放松不会变成全局可行性结论。新增三项测试覆盖偏移变化、解副本隔离、变量上界、大整数溢出、预算耗尽和 256 组随机有限域穷举对照。

完成材料重放的方案携带内部证明，导出时仅在原方案实例、原图快照、相同目标与数量全部匹配时复用，避免再次构建相同材料图。复制方案、调整库存/缺失、换图或改请求均无法复用该证明；两项防误用测试检查不可变配方映射和复制方案后的库存校验。

规划器在没有副产物和已编译反馈组件时直接跳过启动种子扫描，避免为普通 DAG 构建临时映射。唯一材料顺序的线性扫描直接读取库存，移除剩余库存映射；成本传播复用免费库存阶段的临时成本数组，循环策略回退利用连续发现序号直接重建顺序，将装箱排序替换为线性数组填充。材料和配方列表使用索引访问，减少迭代器分配。新增回归验证最低成本标签形成环时，仍能按原发现顺序选择外部原料路由。

Forge 的 `thunderbolt.maxConsumptionOptimizationNanos` 系统属性覆盖保持可用，默认优化预算保持 2.8 秒。GTL 调度、依赖和加载器版本没有调整。

## 验证

Alpha 移植最初的 151 项定向测试全部通过，整数解复用与材料供给的新增定向验证也通过。Java 17.0.20、Forge 47.1.3、AE2 15.4.10 下最终强制全量重跑：1,313 项单元测试中 1,312 通过、1 项因没有可选 EAEP 运行时而跳过，0 失败/错误；独立冷启动 CP-SAT 测试通过；发布 Jar/refmap 校验通过；强制 `gtlCompat=always` 的 10 项 Forge/AE2 GameTest 全部通过。

首次完整执行因磁盘空间不足，测试二进制报告截断，slim Jar 的重映射复制也失败；该次还出现了共享种子 CP-SAT 测试的一次断言失败。清理可重新生成的旧 JFR JSON 导出后，保留原 JFR 和异常日志，隔离截断结果并强制全量重跑，全部通过。没有修改断言、时间限制或求解器预算；复测通过不能单独证明首次断言失败由磁盘不足引起。

Alpha 单独移植期间，多次全量/定向执行的 4,096 分支材料供给测试超过了既有 3 秒限制；只恢复基线 `MaterialDagOrders` 的隔离测试也超时，一轮全量还出现补货组合期限失败。加入局部整数解复用后，定向和最终全量验证通过，未改变任何测试限时；仍不能因此承诺繁忙机器上稳定的 3 秒余量。各次异常和隔离验证日志均保留在忽略目录。

中间执行也观察到共享种子 CP-SAT 补货断言间歇失败，以及一次固定小图混合路由返回缺失方案；最终定向和全量均通过，但未仅凭复测推断这些波动的根因。新增证明复制测试曾因对既有小图反馈保护行为假设过强而失败，已改为 65 个独立配方直接验证大图保护，随后通过。

## 压测

基线和当前规划器源码均独立快照、编译，基线锁定 `ca182d3`。构建和 GameTest 全部退出后，每个版本分别启动三个独立 JVM，交替前后版本启动顺序，串行测量。JVM 使用 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。

大图每 JVM 预热 3 次、测量 12 次；计时和线程分配统计仅覆盖规划请求，夹具创建和独立 BigInteger 库存/配方重放校验在区间外。会话场景每样本包含 8 次数量探针。表中取三个 JVM 的统计量中位数，p95 使用 nearest-rank；12 样本时 p95 就是该 JVM 最大值，尾延迟仅作观测。

副产物宽图来自此前超时的材料供给夹具，分别请求 1 与 10¹²；每 JVM 预热 1 次、测量 5 次，并在计时外按生产者顺序独立 BigInteger 重放全部配方和库存。该组的 p95 同样等于最大样本，不作为稳定尾延迟承诺。

普通场景前后版本均通过全部重放和见证校验，普通场景没有预算退出，18,000 节点准入场景每 JVM 的 12 次预算退出保持一致。该边界场景的波动不作为优化收益。

副产物场景初次 `after` 第 2 个 JVM 因已知可行图返回缺失方案而触发夹具断言，终止记录已保留。随后只调整夹具记录逻辑，保持请求、生产预算、计时和分配区间不变，记录未完成结果并补足其报告缺失后独立重放，完成剩余测量。该场景反映默认内部求解期限下仍可能未找到可行方案，不宣称稳定耗时收益；可行/未完成结果的时间也不能直接解释为同等完成工作的速度。全部结果和初次中断摘要见 JSON 的 `pressure_limit`。

正式记录的两种数量合计每版本 30 个测量样本，基线 10 个、候选 7 个返回缺失方案；这些样本的 `budgetExhausted` 均为 false，未完成通过 `feasible=false` 及缺失表识别。另有基线 1 个预热样本未完成，初次中断不计入这 30 个样本。记录没有发现补足报告缺失后的库存/输出重放错误，但不证明压力下能稳定找出原图已有的可行方案。

各 JVM 汇总和大图逐样本时间/分配数据见 [JSON](benchmarks/gtl-alpha-replay-20261006.json)，原始源码快照、JVM 输出和验证日志保存在忽略目录 `build/gtl-alpha-replay-20261006/`。

这些测量覆盖合成规划负载，不代表完整 GTLCore/GTCEu/AE2LT 整合包 TPS；三个 JVM 和短样本尾延迟也不足以证明统计显著性。
