# Forge 1.20.1 上游修复同步

保留项目 LGPL 许可证与原有署名，不变更 Minecraft / 加载器 / 模组版本号。

- 来源：上游 `764eee0`（`main`）的库存优先修复。可发射材料按策略允许的真实库存与
  外部供应缺口拆分，覆盖执行计划和大整数预览。预览不提取物品，预留/变体分组策略不绕过。
  移植上游充足/部分/空库存、预留库存、发信器切换、共享材料、输出忽略与宽数量回归。
- 来源：上游 `28a1f25`（`1.20.1`）的 Useless 清理。移除不存在公开 API 的适配及模拟
  测试，把基准放入 `core` 并仅保留规划器/普通 AE2 提取；历史模拟数据不能宣传实际收益。
- Forge 单独修复：AppliedE `0.14.3` 样板类型是 `gripe._90.appliede.me.misc.TransmutationPattern`。
  将识别统一到共享帮助类，测试正确/错误包名与实际发行 JAR 的模块和样板描述符。
- EAEP `1.6.3` 的缩放协议保留；通过可选测试 JAR 参数验证，不强制升级生产依赖。
  NeoECO `20.3.0` / `20.4.2` 缺少 allocated API 时继续不注册并普通派发。

Issue #5 的 V2 非全局最优限制仍存在：本次上游没有提供该问题的新修复，不以启发式
结果冒充全局最优。保留已找到的等库存混合配方实例作为后续优化依据。

游戏内提交/多方块执行不在 JVM 单元与协议测试的证明范围内。

## 验证

- Java 17 / Minecraft 1.20.1 / Forge 47.1.3 / AE2 15.4.10。
- `test` 定向回归 29 项全通过；`build optimizationBenchmark --offline --no-daemon`
  全量 903 项、902 通过、1 项未提供 EAEP 运行时 JAR 而跳过，`verifyReleaseJar` 通过。
- 发布 JAR 无 Useless 类，保留许可证；核心基准仅含规划器和普通 AE2 提取场景。
- AppliedE 发行包只作测试二进制依赖，不捆绑或添加到生产运行依赖。
- 额外压力/实际 EAEP 缩放协议测试 14 项全通过、无跳过。2000 组发信器开关对照
  （6000 次计算）库存分配不一致由 2000 组降为 0；8 线程 4000 次计算、2000 层链和
  10 万次大整数存储操作继续通过。随机配方仍有非最少执行次数情况，未算作本次修复。
