# CP-SAT 与 Petri 执行验证的闭环

## 生产路径

本实现位于独立的 `CpSatPlanningEngine` 路径。整数内核仍是 OR-Tools CP-SAT，没有引入 Python、Z3 或外部 Petri 工具。默认 V2 保持独立，也没有把 CP-SAT 的中间结果交给 V2 补全。

借鉴的是 [SMPT](https://github.com/nicolasAmat/SMPT) 与 [Petri 状态方程 CEGAR](https://arxiv.org/abs/1208.2159) 的分层思路：物料余额提出候选，执行顺序验证候选，再用有证明的约束继续搜索。代码为独立实现，不是移植 SMPT 的 PDR、量词推理或完整可达性算法。

CP-SAT 原本已经在切环之前对完整候选 SCC 做准入，通过比例守恒或正权重非增长证明的 SCC 共用 rank，允许同一方案使用环的多个方向。原来的缺口是：固定配方次数回放时发现启动不足，只追加种子 Missing，不再重新选择配方。现在普通消耗型环在这种情况下进入有界细化：

1. 保留已有回放证明的可执行方案或补料方案。
2. 对 CP-SAT 的配方次数和原始 Missing 验证实际可执行顺序。
3. 确证不可执行时，加入排除约束；搜索截断或超时只得到 `UNKNOWN`，不排除候选。
4. 继续询问是否存在每种 Missing 都不增加、至少一种减少的候选。
5. 新候选必须经回放或执行证书验证才能替换旧方案。预算耗尽保留旧方案，设置内部 `budgetExhausted`。

新验证器只处理普通消耗输入。含归还催化物、有限耐久工具、host 私有可复用库存池的图继续采用原有专门模型与回放；容器返还等已规范化的普通副产物可以进入新验证器。未经非增长证明的活动环仍受严格 rank 约束。

## 可执行证书与排除条件

固定配方次数 `x` 后，完整库存由“初始库存 + 已执行次数的净变化”唯一决定，所以剩余次数向量可以用作搜索状态键。每个启用配方都有一次执行分支；连续最大批次仅作为加速分支，失败后仍会回溯一次执行分支，不能把贪心死锁当成不可达证明。

一次执行块记录初始需求 `required` 和净变化 `delta`。连接两个执行块时逐物料计算：

```
required(A; B) = max(required(A), required(B) - delta(A))
delta(A; B)    = delta(A) + delta(B)
required(A^n) = required(A) + (n - 1) * max(-delta(A), 0)
```

前缀和净变化使用 `BigInteger`。重复环标记的已执行片段可以按上述公式批量重复，同时受所有外部输入、输出及剩余配方次数约束；万亿次环不按请求量建立时间层或布尔变量。最终目标取出也加入证书。旧回放不能生成计划时，固定顺序的批次证书还能提供一个充分补料上界，不声称该上界最小。

只有完整搜索穷尽，或最终余额已经违反必要条件，才能证明固定次数 `x*` 在库存加补料 `m*` 下不可达。普通 Petri 网对初始库存单调，因此合法排除约束是：

```
(存在 r: x[r] != x*[r]) 或 (存在 i: missing[i] > m*[i])
```

另外加入“没有执行，或至少有一个选中配方能在初始库存加补料下启动”的必要条件。它能排除完全无法启动的候选；第一步可执行但随后死锁的情况仍由完整验证处理。

## 预算与原生求解

一次 calculation 的数量探测共享最多 16 次额外 CP-SAT 调用、4,096 个验证状态、2,097,152 单位形状工作预算和 250 ms 可选细化时间。每轮可选工作还限制在外层剩余时间的一半内。搜索深度限制为 512 个压缩块；到达限制一律返回 `UNKNOWN`。用户取消及路由截止原样传播，不转成 Missing。

初始 CP-SAT 仍使用路由候选的预算；没有路由上下文的直接调用以 3 秒为上界。原生调用预留四分之一剩余时间给结果回放。含环模型的零缺料快捷探测最多使用 50 ms、且不超过该次原生预算的四分之一；未证明零缺料不可行也可继续正常的分级 Missing 优化。

优化只在 `OPTIMAL` 后固定该级最优值；`FEASIBLE` 或后续优化超时则保留已找到的整数候选，以 `SOLVED_PARTIAL` 跨隔离桥返回，并标记内部预算未完成。它仍须经过实际执行验证。没有整数候选时仍由规划器路由决定后续回退，不能伪造可行结果。

补充了同 rank 组余额行的精确求和约束，显式抵消内部循环；它们都是原模型的推论，不缩小合法解集。系数和域范围无法安全放入 int64 时跳过该冗余行。OR-Tools 9.15 的默认线性传播在测试中的大域亏空环上曾长时间停留，含环模型改用旧线性传播并关闭 probing，保留其他预处理；这组回归现可按预算退出并返回补料候选。截止时间加法也修复了 `nanoTime` 起点为负数时的溢出判断。

## 保证范围与验证

保证的是每个新接受结果都有执行证据，以及补料细化不会接受被当前结果逐项支配的候选。它不证明所有一般 Petri 网可达性，也不宣称全局 Pareto 最优。配方准入、主产物需求约束、int64 域和搜索预算仍构成边界；有限预算下可能多报材料。

回归包含：

- 无种子的短环与有库存的较长路线竞争，修复前误报 Missing，修复后选可执行路线。
- 初始有一步可执行、后续死锁的短路线与可执行替代路线竞争。
- 同一加权转换环必须同时执行两个方向。
- 1,000 个固定随机小型 Petri 网，与独立逐次执行穷举比较正反结论及证书。
- 50 组保守三状态环的库存/需求组合，独立穷举原计划与补料后重新规划的计划。
- 万亿次重复块、最大批次选择错误后的回溯、共享探测预算、搜索未知不生成排除、可选截止恢复和外部取消传播。

这些测试验证规划模型和执行顺序证书；不替代游戏内真实机器和 AE2 网络的运行测试。
