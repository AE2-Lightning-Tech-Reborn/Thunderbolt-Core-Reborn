# CP-SAT 与 Petri 执行验证的闭环

## 生产路径

本实现位于独立的 `CpSatPlanningEngine` 路径。整数内核仍是 OR-Tools CP-SAT，没有引入 Python、Z3 或外部 Petri 工具。默认 V2 保持独立，也没有把 CP-SAT 的中间结果交给 V2 补全。

借鉴的是 [SMPT](https://github.com/nicolasAmat/SMPT) 与 [Petri 状态方程 CEGAR](https://arxiv.org/abs/1208.2159) 的分层思路：物料余额提出候选，执行顺序验证候选，再用有证明的约束继续搜索。代码为独立实现，不是移植 SMPT 的 PDR、量词推理或完整可达性算法。

CP-SAT 在切环之前对完整候选 SCC 做准入，通过比例守恒或正权重非增长证明的 SCC 共用 rank，允许同一方案使用环的多个方向。原来的缺口是：固定配方次数回放时发现启动不足，只追加种子 Missing，不再重新选择配方。现在普通消耗型环在这种情况下进入有界细化：

1. 保留已有回放证明的可执行方案或补料方案。
2. 对普通消耗型 SCC，构建有限的可执行块模板，让 CP-SAT 联合选择配方、启动方向、种子供给和重复次数。该次查询允许更换补料类型；找到的方案按原有距离分级目标比较。
3. 对主模型选定的配方次数做有预算的反向前缀搜索，改进种子和补料；支配剪枝只发生在剩余次数相同的完整需求向量之间。
4. 对原始 Missing 验证实际顺序。确证不可执行才加入排除约束；搜索截断或超时只得到 `UNKNOWN`。
5. 继续询问是否存在每种 Missing 都不增加、至少一种减少的候选。模板模型无解不参与这类全局排除。
6. 新结果须经回放或独立执行证书检查才能替换旧方案。预算耗尽保留旧方案，设置内部 `budgetExhausted`。

如果一个已验证计划已经达到完整收支模型证明的 Missing 最优值，就直接返回，不进行额外模板或状态搜索。

新验证器只处理普通消耗输入。含归还催化物、有限耐久工具、host 私有可复用库存池的图继续采用原有专门模型与回放；容器返还等已规范化的普通副产物可以进入新验证器。未经非增长证明的活动环仍受严格 rank 约束。

## 补料叶子的定义

- 普通无环依赖必须展开到天然原料；不允许因为禁用某个生产配方、或预算耗尽，就把任意中间品变成缺料叶子。
- 保留完整环时，启动种子与外部消耗料是该环对外的供料边界，可以报告种子，也可以选择从上游原料制造种子。
- 切环时，环上选定的切点可作为当前方案的叶子。未收缩的环若在某物料处报告 Missing，其环内入向生产配方必须被切掉；选择和约束在 CP-SAT 内完成。
- 主产物依赖之外，还保留副产物形成的结构性 SCC。即使某 SCC 没通过非增长证明，其切点也不能被误当成普通无环中间品。

不具备非增长证明的副产物反馈，在切边处不再把循环返还计入本计划的可用供应；实际返还仍是正常余料。这样 `A+R→T+2A` 可以按每次外供一份 A 的 DAG 方案合成 T，而不会利用未准入的增益回路。未准入的主产物自环也不能仅因输入输出 rank 相同而直接执行。

种子、消耗料、切点只在内部区分。对外仍输出统一 Missing 清单，每项使用真实物料坐标；更换种子或切点后也在同一坐标下比较支配。只穷尽一个切点不能声称全局 Pareto 最优。

## 联合执行块模型

`PetriBlockCatalog` 收集单配方批次、已有严格环的固定执行比例及顺序、少量可证明的重复片段。每个被编码的 rank 有 4 个阶段，每阶段选择一个真实块以及一个整数重复次数。块的原配方执行次数之和与主模型的 `x` 相等，阶段之间传递内部库存并约束完整启动前缀。外部供应、共享库存和主产物需求仍用同一套全局约束，外部种子生产配方也属于对应阶段，不能提前无条件借用其产出。

模板覆盖的是合法执行序列的子集。模板不足、模板数值域不足、模板模型无解或超时，都不能证明原网络无解，也不能生成排除约束。现有完整收支模型和执行验证继续保留。

`PetriExecutionTrace` 使用不可变的单配方、顺序连接、固定子块重复结构。独立检查器从编译后的配方弧重新计算次数、前缀需求和净变化，以 `BigInteger` 检查补料后的执行及最终目标；不信任求解器或模板传来的汇总数字。切边处忽略的副产物只会增加实际库存，不会削弱证书的可执行性。

`PetriReplenishmentSearch` 是固定执行次数下的反向覆盖搜索，并非完整 PDR。反向步骤计算 `max(H, required−delta)`；比较完整需求向量，同时把剩余配方次数纳入状态键。不能在尚未完成展开时，仅按扣库存后的 Missing 剪枝。这个阶段只提供正向可核验的改进证书，不输出否定排除证明。

## 可执行证书与排除条件

固定配方次数 `x` 后，完整库存由“初始库存 + 已执行次数的净变化”唯一决定，所以剩余次数向量可以用作搜索状态键。每个启用配方都有一次执行分支；连续最大批次仅作为加速分支，失败后仍会回溯一次执行分支，不能把贪心死锁当成不可达证明。

一次执行块记录初始需求 `required` 和净变化 `delta`。连接两个执行块时逐物料计算：

```
required(A; B) = max(required(A), required(B) - delta(A))
delta(A; B)    = delta(A) + delta(B)
required(A^n) = required(A) + (n - 1) * max(-delta(A), 0)
```

前缀和净变化使用 `BigInteger`。重复环标记的已执行片段可以按上述公式批量重复，同时受所有外部输入、输出及剩余配方次数约束；万亿次环不按请求量建立时间层或布尔变量。最终目标取出也加入证书。旧回放不能生成计划时，固定顺序的批次证书还能提供一个充分补料上界，不声称该上界最小。

只有完整搜索穷尽，或最终余额已经违反必要条件，才能证明固定次数 `x*` 在库存加补料 `m*` 下不可达。普通 Petri 网对初始库存单调，因此合法排除约束是：

```
(存在 r: x[r] != x*[r]) 或 (存在 i: missing[i] > m*[i])
```

另外加入“没有执行，或至少有一个选中配方能在初始库存加补料下启动”的必要条件。它能排除完全无法启动的候选；第一步可执行但随后死锁的情况仍由完整验证处理。

## 预算与原生求解

一次 calculation 的数量探测共享最多 16 轮额外主模型查询（分级优化可能在一轮内调用原生求解器多次）、4,096 个验证/反向搜索状态、2,097,152 单位形状工作预算和 250 ms 可选细化时间。执行块查询也计入这些轮数和时间，不单独重置预算。每轮可选工作还限制在外层剩余时间的一半内。搜索深度限制为 512 个压缩块；到达限制不能产生否定证明。用户取消及路由截止原样传播，不转成 Missing。

执行块最多 96 个，最多编码 16 个循环 rank、48 个相关配方，单个 rank 最多 12 个配方；超出时保留原路径。片段发现最多 8,192 次形状探测，并按物料/配方维度收紧工作上限。反向改进每轮最多展开 128 个状态，消耗共享验证预算。模型大小不会按请求执行次数展开，但依然随图结构及模板数量增长。

初始 CP-SAT 仍使用路由候选的预算；没有路由上下文的直接调用以 3 秒为上界。原生调用预留四分之一剩余时间给结果回放。含环模型的零缺料快捷探测最多使用 50 ms、且不超过该次原生预算的四分之一；未证明零缺料不可行也可继续正常的分级 Missing 优化。

优化只在 `OPTIMAL` 后固定该级最优值；`FEASIBLE` 或后续优化超时则保留已找到的整数候选，以 `SOLVED_PARTIAL` 跨隔离桥返回，并标记内部预算未完成。它仍须经过实际执行验证。没有整数候选时仍由规划器路由决定后续回退，不能伪造可行结果。

同 rank 组余额行的精确求和约束显式抵消内部循环；系数和域范围无法安全放入 int64 时跳过该冗余行。还检查整个编译网络的空 siphon：若一个状态集合没有任何不消耗它就向其中生产的配方，初始为空时，活动消费者必须获得至少一个种子。存在外部种子生产配方时不应用该限制，避免错杀“先造种子”的路线。

OR-Tools 9.15 的默认线性传播在测试中的大域亏空环上曾长时间停留，含环模型改用旧线性传播并关闭 probing，保留其他预处理。截止时间加法处理了 `nanoTime` 起点为负数时的溢出边界。

## 保证范围与验证

保证的是每个新接受结果都有执行证据，以及补料细化不会接受被当前结果逐项支配的候选。它不证明所有一般 Petri 网可达性，也不宣称全局 Pareto 最优。配方准入、主产物需求约束、int64 域和搜索预算仍构成边界；有限预算下可能多报材料。

回归包含：

- 无种子的短环与有库存的较长路线竞争，修复前误报 Missing，修复后选可执行路线。
- 初始有一步可执行、后续死锁的短路线与可执行替代路线竞争。
- 同一加权转换环必须同时执行两个方向。
- 1,000 个固定随机小型 Petri 网，与独立逐次执行穷举比较正反结论及证书。
- 50 组保守三状态环的库存/需求组合，独立穷举原计划与补料后重新规划的计划。
- 万亿次重复块与从库存制造启动种子的联合选择，多个环对同一物理原料的竞争。
- 直接补种子、反向启动、主产物切点、副产物闭环切点、未准入自增反馈的保守供料。
- 200 个随机小网的固定次数反向补料，与独立逐次枚举全部执行顺序比较最小补料及边界合法性。
- 最大批次选择错误后的回溯、共享探测预算、搜索未知不生成排除、可选截止恢复和外部取消传播。
- 可选执行块数值域不足时保留已验证补料；固定次数验证预算为零时不生成排除，补齐后重新规划仍可执行。

这些测试验证规划模型和执行顺序证书；不替代游戏内真实机器和 AE2 网络的运行测试。
