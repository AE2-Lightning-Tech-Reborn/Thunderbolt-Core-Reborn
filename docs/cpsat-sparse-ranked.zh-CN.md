# 含环与状态输入的 CP-SAT 稀疏排名模型

原排名模型现已全程使用稀疏物料矩阵。目标相关图中有副产物、容器返还、有限耐久、催化剂、私有种子或环时，仍保留原排名、种子、执行块及复核约束，但不再回到五张 `配方数 × 物料数` 的稠密 long 表。

## 表示与约束

`SparseLongMatrix` 只存储实际非零弧，并提供稳定有序的行、列索引。跨隔离类加载器的传递格式仍只包含基本 Java 数组：一个维度头，加上各行的“列号、数值”对；不传递模组类型或 OR-Tools 类型。矩阵修改会使相关索引失效，删除循环副产物信用后不会沿用过期索引。

编译、原生模型构建、普通执行回放、Petri 验证、执行块发现和补料搜索都读取同一套稀疏数据。有限耐久的批次数变量也只在真实工具输入处创建，不再分配另一张全尺寸对象表。保留的小型数组包括按物料计的库存向量、固定数量的执行块证书及有预算约束的反馈候选，不按整图配方与物料的乘积创建常驻矩阵。

库存平衡、主产物需求与末批余量、有限耐久取整、私有库存竞争、催化剂预留、rank 依赖、循环守恒割和执行块约束保持原有含义。按稳定索引构建稀疏表达式；不跳过种子校验，不把一条特殊配方从整图中单独解出。

各物料行只枚举实际关联的配方。执行回放先按 rank 组索引配方，再访问该配方的实际输入输出；私有输入对应的物料也加入独立 rank 复核，不能因它们不在普通消耗表中而漏检。

建模时间现在计入传入原生桥接的时间预算。缺料优化跳过被固定为零的物料层，避免万层链附带一个环时按万层重复调用原生求解器。优化超时后仍导出已保留的候选解，并交给调用方按原规则做执行复核；不能在导出阶段因优化预算已耗尽而把候选解重新降为 `UNKNOWN`。没有在超时或仅有界搜索失败时增加“不可能执行”的排除约束。

## 验证

新增独立稠密参考表的随机读写、转置索引失效、稀疏传递及非法输入测试。一个逻辑大小为 10,000 × 10,000、只有对角线上 10,000 条弧的矩阵，传递格式只含 20,002 个 long。另有千配方混合图测试，以及原有 CP-SAT、环、返还、耐久、私有库存与独立 Petri 执行校验回归。最终全量测试共 798 项，全部通过。

受限内存实测把一张 10,000 配方链分别接上副产物、容器、有限耐久、催化剂、私有种子、守恒转换环和副产物反馈环。Java 堆限制为 256 MB、单次预算为 3 秒，请求量分别为 1 和 10¹²。七类共 14 次均得到可行解，普通状态类约 0.65～0.68 秒，含环类约 0.96～1.00 秒。计时不包含首次原生库加载，Java 堆上限不包含原生库内存。

这解决的是整图稠密表示及零元素扫描问题，不意味着所有复杂图都能在 3 秒内求得最优解。候选模板、整数搜索和 Petri 验证仍保留各自原有的正确性门槛及预算。
