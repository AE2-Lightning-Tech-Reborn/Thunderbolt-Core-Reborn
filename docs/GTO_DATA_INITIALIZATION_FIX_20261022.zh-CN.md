# GTO 客户端数据初始化兼容修复

本轮继续处理前一份 [I/O 与客户端修复记录](GTO_IO_CLIENT_FIX_20261022.zh-CN.md) 留下的 GTO 数据加载和 EMI 重载问题。修改仅位于 Thunderbolt 当前项目，继续排除 NeoECO。

## 原因与实现

核对 GTOCore 26.10.5 原包字节码后确认：`Data.init()` 在物理客户端通过 `GTOUtils.asyncExecute` 执行 `clientInit()`，其中依次生成配方、战利品和 EMI 数据。首次数据包加载可以与这个任务重叠。`GTOLoots.apply()` 会将 `DYNAMIC_LOOT` 合入缓存后置为 `null`；此时后台任务若尚未执行 `RewardBagLoot.init()`，随后调用 `addToot()` 就会空指针，奖励袋表也不会进入首次战利品缓存。

新增 `gto_data_initialization.js`，只在 `Data.init()` 原有的异步提交前包装 `Runnable`，记录完成状态。GTO 的线程池、异步任务内容和服务端同步分支继续使用原实现。转换器检查目标签名及唯一提交点，遇到不符合预期的实现就报错。

Thunderbolt 在 Forge `FMLLoadCompleteEvent` 的排队任务中等待该后台任务完成，随后才允许首次客户端数据包加载。等待通过 Future 建立可见性，最长五分钟；中断、超时和未捕获的任务异常会保留原因并终止启动。GTO 自行捕获的初始化异常则通过其 `Data.getThrowable()` 读取并原样作为失败原因。不会跳过配方、重新创建已清空的战利品表或吞掉异常。

专用服务端没有这个异步提交，等待入口直接返回，不解析客户端类，也不改变服务端的数据初始化顺序。

## 验证方式

环境：Minecraft 1.20.1、Forge 47.4.20、Java 21、GTOCore 26.10.5、AE2-GTO 15.2610.8、AE2LT 2.1.2-gto.1。

先用旧生产包和仅测试用的 60 秒延后加载做对照，成功进入世界并等 EMI 完成后正常退出；没有先前的数据加载或 EMI 关键重载错误。随后换用本次生产包，移除固定延时，执行相同实际启动及退出检查。

新增八项自动测试，覆盖读取方等待最后一次注册并看见普通 Map 的写入、失败后唤醒且保留异常、重复初始化、中断标记、超时，以及实际执行转换后字节码以确认客户端先记录再提交、服务端继续同步初始化。转换器还会拒绝缺失或多出的提交点，拒绝时不部分修改字节码。

测试用客户端探针在真实加载后检查：GTO 初始化异常为空、EMI 完成重载并保持就绪、五张奖励袋战利品表均位于最终缓存。复跑额外检查生产兼容层确实记录并完成了实际 GTO 异步任务。继续复验前台/后台/关闭后的按键查询、精确数量渲染及界面 Mixin。测试探针不进入生产包。

完整 `check` 共 1557 项：1556 通过、1 跳过、0 失败/错误。其中主测试 1534 项，另有冷启动 refinement 1 项、replay 20 项和 replenishment 2 项。跳过项仍为固定 EAEP 制品缺少 `ScaledMolecularAssemblerPattern` 的可选测试，不计为通过。`compileGameTestJava` 与 `verifyReleaseJar` 通过。

实际专用服务器最终 I/O 套件 47/47 通过，CPU、STORAGE、PLANNER 三个启动检查通过，保存所有维度后 JVM 正常退出，退出码 0。首次服务器运行虽然 47 项断言已通过，但监督脚本因可选 `jcmd Thread.print` 超时而中断，未取得 JVM 退出码，不计作完整通过。已在隔离脚本中让该可选诊断超时后继续等候服务器退出，并以新的测试世界重跑取得最终结果；没有放宽功能断言或 JVM 退出码要求。

使用同一冻结生产包的两次正式客户端启动均通过，JVM 退出码均为 0，未开启固定延时。两次均确认五张奖励袋表存在、EMI 就绪、精确数量渲染及 Mixin 审计通过，前台/后台及 JVM 关闭后的按键查询通过；没有数据初始化失败、重复配方、EMI 关键重载或搜索烘焙异常，也没有 JEI 添加配方阶段的停服异常。第二次额外确认真实 GTO 数据任务的完成记录存在。对照客户端同样以 0 正常退出。

## 边界

本轮修复针对以上固定 GTO 版本的初始化时序，不代表所有版本的 GTO、全部可选附属或所有游戏配方均已穷举验证。此前出现过的重复配方错误会继续作为实测失败条件监控；不会用忽略重复 ID 的方式使测试通过。

ProjectE 联网证书检查失败、资源模型/贴图缺失等其他模组的日志问题不由此兼容层处理。客户端和服务端仍需使用配套的 TB/LT 版本，保持 GTO 原包内嵌 AE2，不单独替换为不匹配的新 AE2。
