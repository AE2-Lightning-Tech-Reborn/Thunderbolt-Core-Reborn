# 普通双配方混合批次优化

> 本文保留首轮双配方实现及其验证记录。后续已增加完成/耗尽状态、避免重复扫描、三至六配方有界混合及独立 CP-SAT 冷启动检查，当前范围和验证请见[后续优化记录](bounded-optimizer-followup.zh-CN.md)。

## 目标与适用范围

在已认证可行计划上，允许两种普通配方共同完成请求，解决“任一单配方都不合适、混合后可减少执行次数”的情况。例如 8T←12raw 与 2T←3raw 请求 19：两种各执行两次可用 30raw 产出 20T，代替 10 次执行。

仅处理目标有恰好两种配方、输入都是直接库存原料、没有副产物/容器返还/催化剂/私有库存/中间配方的情况。不增加原计划任何原料提取，保留已使用的目标库存、原样板对象及预算诊断。

## 算法与安全边界

- 使用 BigInteger 有理数计算连续执行次数下界，再从下界开始检查整数执行次数；固定总次数时，输出和各原料库存约束化为一种配方次数的上下界。
- 找到第一个可行整数次数后，以原料总提取量为同次数取舍，使用原始精确配方数量重建并校验完整候选。执行次数优先，原料逐项不增，不把浮点近似当作证书。
- 搜索不按请求数量逐个枚举：上限为 4096 工作单位、32 个输入槽和 8 种原料；费用从计算会话的共享搜索预算扣除。巨大整数间隙、工作量不足或不适用时返回无候选，而不是证明不可行。
- 与上游通用优化器共用时间和最多 32 次探测预算；可选超时保留最后完成的计划，外部取消继续传播。不缓存数量及库存相关的可变结果。
- 新路径位于 OptionalPlanningStages，不改变公开 V2 接口、Forge 版本或可选模组依赖。其他图形继续使用同步后的上游优化器。

该优化并不证明整合包图的全局最优，也不代表 Issue #5 的完整报告已修复。游戏内合成提交与多方块执行仍需另外验证。

## 验证

- Java 17 / Minecraft 1.20.1 / Forge 47.1.3 / AE2 15.4.10，全量构建和发布 JAR 校验通过。
- 全量回归 918 项，917 通过、1 可选 EAEP 运行时测试跳过；独立压力 16 项全通过。此后补充的 AE2 导出测试与该组一起独立运行，20 项全通过；最后这一测试未再次纳入全量运行，生产代码及发布包没有再变更。
- 新增固定反例、万亿数量、重复输入槽/目标库存、3000 组双配方独立整数枚举、1000 组多原料枚举、巨大整数间隙限额、超时/取消、饱和与不适用路径回归。
- 相同种子 3000 个压力样本中，等或更少库存可减少执行次数的遗漏由 10 降为 0；不考虑库存约束的非最少次数样本由 228 降为 222。余下差异在该样本内需要更多库存，不改变“不增加已有库存提取”的取舍。
- 原 10 次/30raw 反例现为 4 次/30raw，独立压力反例测试通过；并发 4000 次规划、2000 层链、6000 次发信器切换、10 万次大整数存储操作及真实 EAEP 1.6.3 协议继续通过。
- 修复 AE2 计划转换测试的注册表初始化依赖，使该组可以单独运行；新增适配器完整路径测试，验证导出两种原始样板次数、材料提取及规划不修改实际库存。
- 本次微基准没有普遍提速：单数量和会话耗时存在涨跌，不将候选质量改善宣传为整合包 TPS 收益。历史同步报告中的“反例未解决”仅代表当时状态，当前范围以上述验证为准。
