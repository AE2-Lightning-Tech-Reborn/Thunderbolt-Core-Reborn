# Forge 1.20.1_GTL：副产物预处理分配优化

本轮以 `5a4480d` 为基线，继续比对上游 alpha 的规划器优化，将索引遍历的做法应用到 GTL 尚未覆盖的副产物预处理路径。适用环境为 Minecraft 1.20.1、Forge 47.1.3、Java 17、Windows x64；开发与验证保留在本地。

## 实现

`lowWidthByproductSchedule` 原先在强连通分量分析后，为每个分量创建物料成员集合，再只查询存在副产物环的分量。现在先标记这些分量，必要时按原始物料顺序扫描一次收集成员。安全分量不再分配成员集合，时间复杂度仍为线性。副产物屏障不作为物料行加入不安全集合。

分量分析中的副产物与输入 `anyMatch` 改为索引遍历，保留原有访问顺序和短路条件；副产物调度的路线、输入和输出扫描同样采用索引遍历。读取已有消费者集合时避免创建不会使用的默认空集合。

新增元数据回归覆盖两个独立副产物环、同一生产者的重复环链接、环内没有副产物的中间节点，以及独立安全副产物。分别检查全部链接不安全和安全/不安全链接混合的路径，验证成员集合、配方身份与生产者先行顺序。

## 压测方法

基线与候选使用相同的已构建类及依赖，只在类路径首项覆盖各自独立编译的 `CraftPlannerV2` 和内部类。使用 Java 17、G1、256 MiB 初始堆、2 GiB 最大堆、4 个活动处理器。每个版本运行三个独立 JVM，交替版本顺序；Gradle 和 GameTest 与压测分开执行。

4096 分支完整规划分别请求 1 与 10¹²：每个 JVM 预热 1 次、测量 5 次，调用方截止时间 15 秒。普通规划使用既有长链、宽图、会话、无关图和准入夹具，每个 JVM 预热 3 次、测量 12 次。最终物料证书使用既有独立夹具，每个 JVM 预热 3 次、测量 12 次。耗时与线程分配量不包含独立重放。

完整方案通过独立 `BigInteger` 供给顺序重放验证库存、逐步消耗及最终产量。缺失方案和预热失败也保留记录，不用于宣称等量完成工作的提速。准入宽图 18000 按夹具预期退出预算。所有原始样本见配套 JSON。

## 结果

以下取三个 JVM 的摘要中位数：

| 场景 | 基线 p50 | 本轮 p50 | 基线分配量 | 本轮分配量 |
| --- | ---: | ---: | ---: | ---: |
| 4096 分支，数量 1 | 1057.425 ms | 890.965 ms | 169.225 MiB | 159.537 MiB |
| 4096 分支，数量 10¹² | 812.881 ms | 904.638 ms | 175.667 MiB | 165.915 MiB |
| 长链 10000 | 31.234 ms | 30.281 ms | 6.858 MiB | 6.785 MiB |
| 宽图 16000 | 62.104 ms | 61.972 ms | 14.837 MiB | 14.826 MiB |
| 会话宽图 4096，8 次请求 | 25.370 ms | 46.520 ms | 12.777 MiB | 12.777 MiB |
| 会话长链 2000，8 次请求 | 28.241 ms | 24.229 ms | 5.721 MiB | 5.721 MiB |
| 宽图 256，加 100000 个无关项目 | 0.564 ms | 0.560 ms | 0.242 MiB | 0.242 MiB |
| 准入宽图 18000 | 8.881 ms | 6.617 ms | 1.529 MiB | 1.529 MiB |
| 最终物料证书，数量 1 | 43.471 ms | 50.936 ms | 12.426 MiB | 12.895 MiB |
| 最终物料证书，数量 10¹² | 73.869 ms | 86.722 ms | 16.462 MiB | 16.833 MiB |

4096 分支的两种数量分别减少 **5.7% / 5.6%** 分配量，约 **9.7 MiB / 9.8 MiB**。两版本各 30 个测量样本和 6 次预热全部可行，没有预算退出，均通过独立重放。普通规划和证书样本也全部通过相应验证；准入场景两版本各 36 个测量样本按预期退出预算。

本轮只确认宽副产物图的分配量改善。万亿数量、会话宽图及最终证书的中位耗时更慢；最终证书实现本轮没有修改。JVM 间波动明显，不能据此宣称整体提速，也不能将所有较慢结果直接归因为已证明的环境噪声。

## 验证记录

首轮定向测试 100 项中 98 项通过、2 项失败，新增元数据回归通过。失败为 `MaterialDagBudgetTest` 的最小搜索证书及补货预算用例。随后独立 JVM 首轮对照中，基线 10 次通过，候选 7 次通过、3 次失败；失败集中在前两轮调用。再以交替版本顺序运行三个独立 JVM，每个 JVM 调用两项用例各 5 次，基线与候选各 30 次全部通过。产品预算及测试时间限制没有调整；首次失败与修改的关系尚未证明，保留全部记录。

第一次完整测试共 1320 项：1318 通过、1 项可选 EAEP 集成跳过、1 项失败。失败为 CP-SAT 共享种子用例 `independentCyclesShareTheSamePhysicalSeedMaterial` 在补齐库存后的可行性断言；该用例使用 1 秒 session 预算。直接调用的 CP-SAT 求解路径不经过本轮修改的 `CraftPlannerV2`。独立 JVM 正确执行原生初始化后，候选 4/5 次通过、基线 5/5 次通过，仍保留候选的失败。最初独立探针遗漏测试类的 `BeforeAll` 初始化，产生 `UNSUPPORTED`，已单独标记为无效夹具，不计入有效验证。

最终完整复核 **1320 项：1319 通过、1 项可选 EAEP 集成跳过、0 失败、0 错误**。独立 JVM 的 **CP-SAT 冷启动 1/1 通过**，**发行 Jar/refmap 检查通过**。复核没有修改产品、测试断言或预算，也没有排除任何测试；前述失败记录继续保留。

Forge 47.1.3、Java 17、真实 AE2、强制 `gtlCompat=always` 的 **10 项 GameTest 全部通过**。该夹具未安装 GTLCore，验证的是强制兼容模式中的规划与调度边界。最终发行包为 `build/libs/thunderbolt-forge-1.20.1-2.0.0.jar`，SHA-256 见配套 JSON。

最终完整测试、CP-SAT 冷启动、发行 Jar/refmap 与真实 AE2 GameTest 结果见 [验证记录](validation/gtl-byproduct-preprocessing-20261006.json)。原始本机日志保留在忽略的 `build/gtl-preprocessing-20261006/`，不提交开发环境日志。
