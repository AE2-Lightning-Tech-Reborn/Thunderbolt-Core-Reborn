# V2 小图反例修复与保留边界

## 本次修复

- 按实际选中的配方重新检查反馈启动前缀。未选用的替代配方即使把整个 SCC 变成无法分类的结构，也不能让返还物资支付自己的首次输入。已有精确启动证明不重复加料。
- 补料重算缺少启动种子时，尝试用主计划尚未占用的库存先制造种子。前置计划与主计划不得重复提取同一份库存。
- 保留原有 DFS 重排，增加明确删除环内生产入口的切点候选。复杂 SCC 可以使用多个切点；从切点向外分层，并处理同层依赖。环外生产路径继续保留。
- 当缺料落在替代路线的原料上，仍允许检查被遮蔽的切点。两类候选共用原来的 16 次重试和会话预算。
- 单配方副产物图也存在“取库存主产物还是制造主产物”的分配选择。已有整数模型可以处理这项选择；回放为选定配方保留实际主产物需求，并先获取能提供兄弟副产物的输入。
- 自增回边被该次 DAG 真正删除后，不再因为这条已删除的配方禁用正常副产物。保留下来的自增反馈仍受原有抑制规则约束。

## 语义边界

自增环仍需裁切，不因物理状态搜索找到一条路径就准入。为了副产物而额外制造完全不需要的主产物也仍不支持。已有主产物需求可以分配给制造路线，同时保留库存中的同种成品。

这次不是所有非预算假阴性的清零。V2 仍以 DAG 候选为主；需要保留完整守恒环的请求可以继续漏解。例如库存 A=1、C=1，配方为：

```text
A + C -> 2B
B -> A
A + B -> 2C
2C -> T
```

完整执行四条配方可以得到 T。当前 CP-SAT 路径可解，V2 仍会报告启动材料。这个限制不属于自增环，也没有被记作预算耗尽。它需要进一步统一完整环的计数求解与可执行性证明。

## 验证方法与结果

使用原来的固定随机种子和完全相同的 43,000 张图：普通配方 10,000、重点切环 30,000、副产物 3,000。逐图核对输入与修复前语料一致。独立有限状态搜索与 Python 单次 firing 搜索检查计划，不调用规划器自己的执行证明。

| 检查 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 不可执行的初始计划 | 7 | 0 |
| 补足报告材料后仍报缺料 | 1 | 0 |
| 不可执行的补料重算计划 | 2 | 0 |
| 原来报缺料、现在可执行的计划 | — | 128 |
| 原来可执行、现在变成缺料的计划 | — | 0 |

修复后独立检查了 43,000 份初始计划和 14,805 份补料重算计划，均可执行。一次原来声称可行的计划改为缺料；它正是已确认无法执行的副产物反例 253。

仍能找到合法无环路径却报告缺料的普通配方图为 3 张，均触及候选搜索上限；重点切环图没有此类剩余案例。副产物图还包含预算触顶，以及必须额外制造无需求主产物的路径。这个分类不能用来掩盖上文完整守恒环的非预算漏解。

新候选增加了部分难图的工作量和预算触顶标记，但不按合成次数逐次展开，也没有提高原有重试上限。该次本机审计中 V2 的 P95 为普通图约 0.40 ms、重点切环约 0.23 ms、副产物约 0.95 ms；这是该语料的观察值，不是跨机器性能保证。

`SmallGraphRegressionTest` 固定了首次执行、补料重算、库存隔离、多切点、切点归因、主产物库存分配、副产物顺序及两项保留规则的反例。运行方式：

```shell
./gradlew test --tests '*SmallGraphRegressionTest'
./gradlew build
```
