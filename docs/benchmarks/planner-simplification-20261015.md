# TB v2 精简与消融，2026-10-15

基线为 Reborn `origin/alpha` 的 `4b59ae736f1c0a13a007b57c7b6ad87ca8e0d210`，Minecraft 1.21.1 / Java 21。

## 决策

本轮没有删除任何具有已知收益的规划搜索阶段。逐个禁用 10 个阶段后，每个阶段都出现了合成次数增加的反例。减少规划器源码不能以增加机器实际执行次数为代价。最终生产改动仅统一三个混合搜索阶段重复的预算扣费和探测预留逻辑，并让关闭的诊断跟踪不再分配列表、装箱每次探测时间、计算仅供诊断的库存总量或读取诊断时钟。实际截止时间和停滞时钟保持启用。

`FeasibleConsumptionOptimizer.java` 从 1565 行减少到 1545 行；搜索空间和渐近复杂度没有变化。这里是有限精简，不代表 TB v2 的整体算法已被缩减。

## 复现

编译测试夹具，导出测试运行类路径，再运行：

```sh
./gradlew -I scripts/benchmarks/test-classpath.init.gradle \
  -PplannerAuditClasspath=/absolute/path/to/test-classpath.txt \
  writePlannerAuditClasspath --offline
python3 scripts/benchmarks/planner-ablation.py \
  --classpath-file /absolute/path/to/test-classpath.txt \
  --output /absolute/path/to/new-output-directory
```

脚本从指定 Git 基线读取优化器，在输出目录生成临时禁用开关，不修改生产源文件。除该优化器外的生产源若偏离基线则拒绝运行，避免将不同规划器误作消融对比。可通过 `--variants baseline candidate` 只复查最终候选。单次运行的耗时和分配量保留在原始 CSV，消融表不把这些单次时序视为稳定性能结论。

## 验证

完整单元测试 1290 项，0 失败、0 错误、2 项原有跳过。最终候选在 3339 个样例上的上述结果字段与基线完全相同，并通过独立执行回放。与 LT 联合运行时使用 `-Pmod_version=2.0.3-beta2` 打包，以满足 LT alpha 声明的最低版本；没有修改仓库默认发布版本。

另做独立 JVM 的顺序 A/B/B/A 对照，每次先预热 500 个样例再测全部 3339 个。基线两次累计规划耗时 9.413 / 9.374 秒，候选 9.409 / 9.419 秒；分配总量分别为 16.637 / 16.728 GB 与 16.619 / 16.555 GB。整个规划器的差异处在波动范围，不能宣称明显加速；默认关闭诊断时的无效采集已从代码路径移除。四次结果均一致且独立回放通过。
