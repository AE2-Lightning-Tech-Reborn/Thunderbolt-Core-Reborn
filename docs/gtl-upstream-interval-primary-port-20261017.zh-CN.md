# Forge 1.20.1 整数区间与主产物规划移植记录（2026-10-17）

本轮将上游 Forge `1.20.1` 的 [`ee79119`](https://github.com/AE2-Lightning-Tech-Reborn/Thunderbolt-Core-Reborn/commit/ee79119) 与 [`a49351a`](https://github.com/AE2-Lightning-Tech-Reborn/Thunderbolt-Core-Reborn/commit/a49351a) 整合到 `1.20.1_GTL`，基线为 `9fe2419e40ea555703497a288668885ba96ee412`。原项目许可证和必要署名继续适用。

## 移植范围

1. **整数批次区间。** 用统一的 `IntegerInterval` 处理有符号线性不等式与精确整数端点；多路线搜索将最后两条路线化为区间约束，以端点求最少库存消耗，减少一维枚举。双路线与配对分配复用同一工具，保持预算截止与已认证候选的语义。
2. **正反馈分析。** 按实际补充输入建立索引，用精确乘积比较筛选增长反馈，保留饱和情况下的小批次检查。原图事实在同一次计算的方向与数量探测间共享，切图只重检可能存在的反馈。
3. **主产物候选。** 大型副产物图在完整反馈编译前尝试有界普通候选，使用真实库存精确回放并校验副产物安全。候选不依赖尚未生产的副产物，时间或工作量用尽时保留已完成方案，外部取消继续传播。精确数量预览仍编译完整图。
4. **需求遍历与副产物调度。** 按拓扑顺序仅访问有需求的节点，共享输入在消费者合并后展开；跳过与副产物无关的输入排序，复用回放排名并直接裁剪不安全的调度边。

## GTL 差异整合

- 保留 GTL 已有的循环组件关联索引与输入、输出槽位过滤，避免宽配方在多个组件间重复扫描。将上游组件回归的全表对照适配为独立逐组件扫描，覆盖外部生产者、只读输入和重复输出。
- 保留 GTL 的消耗优化预算辅助方法和已移除的调试追踪代码；保留未解决规划在组合搜索截止时标记预算耗尽的行为。
- 保留多路线的原始配方顺序与 GTL 原有候选保留策略；没有引入来源分支此前独有的排序与单路线预播种逻辑。
- 更正上轮移植报告的汇总计数：该次五个实际执行任务为 1,467 通过、13 跳过；旧汇总混入了其他任务遗留的 XML。
- 测试 JVM 统一使用 `-XX:ActiveProcessorCount=4`，将已有大图任务的处理器配置推广到普通与冷启动任务，稳定 GC/JIT 调度；生产运行参数、求解预算和测试时限不变。
