# 精确需求与动态同 ID 产物混用

复现：目标需要一个精确 `MAT` 和一个接受任意同 ID 变体的材料；库存有一个精确 `MAT` 和一个 `BASE`；配方 `BASE -> 任意 MAT` 的组件在执行时才能确定。有效分配是精确库存供精确槽，动态产物供模糊槽。

原来的图导出将两个需求合并为 `MIXED` 后，直接排除动态产物配方。信息在进入 V2 或 CP-SAT 之前已丢失，因此更换后端不能解决这次假缺料。

现在仅在这种混合需求需要分流时引入计算内部的 `LateBoundOutputKey`：

- 真实库存和确定产物仍使用原物品键，由所有消费者共同竞争，不复制库存。
- 动态产物使用独立资源键，只能连接声明了完整同 ID 接受范围的普通消耗槽。带返回物、耐久和宿主库存的输入不会因此放宽。
- 精确槽仍不能消费动态资源。动态副产物也不能泄漏到精确库存池。
- 无论物品节点是否已经被 BFS 展开，只要发现 `MIXED`，就以确定的需求模式重建消费者选项；重建和新增选项沿用图导出及模糊展开预算。
- 内部键不进入库存清单、缺料显示、网络包或执行输入分配。缺料的普通和超量显示均投影为真实目录键。

同一执行任务内，`ParallelBatchCpuHelper` 先提取具有确定分配的输入，再匹配动态槽，仍按原槽号向提供器返回结果。失败时把所有已取物品回滚，批量缩放与部分接受继续沿用原有路径。

回归覆盖两个槽顺序、V2 与 CP-SAT、不同需求发现顺序、数量探测缓存、共享库存不重复、补料后重算、动态副产物的精确隔离，以及单次/批量取料和失败回滚。修复前的八个混合需求用例均失败。强制先枚举精确库存还复现了模糊槽先取料导致的执行失败。

这里的执行测试覆盖本库的任务内取料助手；跨任务调度、动态实际产物接收以及集成是否消费 `PlannedInputAssignments` 仍属于调用方契约。此修复没有证明任意集成或整合包在运行时不存在卡料。
