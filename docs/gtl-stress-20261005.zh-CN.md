# GTL 分支压测（2026-10-05）

测量版本 `eccbb8d`，规划器对比基线为移植前的 `40930b8`。Java 17.0.20、Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10，独立 JVM 使用 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。测试进程顺序运行，未修改或停止原有游戏实例，因此桌面和游戏负载会影响耗时。原始统计见 [JSON](benchmarks/gtl-stress-20261005.json)，本地夹具、完整日志、类路径和源码哈希在忽略目录 `build/stress-20261005/`。

## 结论

规划、频道容量和存储一致性检查通过，没有观察到 OOM、栈溢出或错误物料回放。最新移植明显减少大图规划的分配量和重复探针耗时。三配方混合出现性能回退线索；极端频道网络一次求解仍可超过一秒，不能据此承诺稳定 TPS。

## 规划器

既有 `OptimizationBenchmark` 每个场景预热 20 轮、测量 20 轮，前后各运行 3 个独立 JVM，顺序交替；下表为三个 JVM 各自 p50 的中位数。每次检查可行性、参考用料或退款后的库存。

| 场景 | 前 p50（µs） | 后 p50（µs） | 前分配（B/次） | 后分配（B/次） |
| --- | ---: | ---: | ---: | ---: |
| 500 层链 | 1,823.290 | 1,262.420 | 1,159,712 | 755,557 |
| 普通双配方选择 | 84.696 | 79.916 | 29,902 | 27,411 |
| 普通数量会话（8 探针） | 184.200 | 153.440 | 99,696 | 93,056 |
| 万亿数量双配方选择 | 62.520 | 64.328 | 31,024 | 28,472 |
| 万亿数量会话（8 探针） | 144.840 | 103.960 | 101,088 | 94,200 |
| 三配方混合 | 440.098 | 853.954 | 160,872 | 157,720 |
| 普通批量提取与退款 | 1.730 | 1.884 | 3,872 | 3,904 |

三配方专项复测增加到 2,000 次预热、40 × 50 次测量，前后各 5 个 JVM，交替顺序。前后 p50 中位数为 **158.694 → 186.132 µs（+17.3%）**，p95 中位数为 279.314 → 461.722 µs，分配为 158,472 → 155,232 B/次。各 JVM p50 范围分别为 143–323 与 142–561 µs，波动明显：首次约 94% 的增幅未稳定复现，但结果也不支持该场景普遍提速。所有结果保持 3 次配方执行、铁和钻石各使用 9 的正确见证；未修改规划器来追逐单机基准。

大型规划夹具每版本运行一个 JVM，每场景预热 3 次、测量 12 次，使用默认规划预算与 15 秒外层合作取消期限。计时不含图构造和独立回放；每个可行计划从实际 `usedStock` 开始按原始 DAG 顺序回放，检查源样板身份、用料和最终目标。

| 图/会话 | 前 p50（ms） | 后 p50（ms） | 后 p95（ms） | 前/后分配（MiB/样本） |
| --- | ---: | ---: | ---: | ---: |
| 10,000 层链 | 44.787 | 37.936 | 69.504 | 23.112 / 13.537 |
| 16,000 条支路 | 82.158 | 38.912 | 86.032 | 42.227 / 27.946 |
| 4,096 支路会话，8 探针 | 49.651 | 21.961 | 30.973 | 34.217 / 26.201 |
| 2,000 层链会话，8 探针 | 21.391 | 17.285 | 20.605 | 16.358 / 12.318 |
| 256 支路 + 100,000 条不可达配方 | 0.843 | 0.725 | 0.967 | 0.682 / 0.455 |
| 18,000 支路，超过准入上限 | 3.741 | 4.502 | 6.882 | 2.497 / 1.529 |

每版本测量 240 次请求。前五个场景全部可行且回放通过，最后一个场景的 12 次请求全部按预期返回预算耗尽，未继续构造越界距离表。12 个样本按 nearest-rank 计算时 p95 等于最大值。会话行的耗时和分配包含 8 个探针。

现有 `ConservativeFeedbackPressureTest` 三项通过：32 状态 / 64 样板的有理势证明 p50 1.747 ms、最大 2.334 ms；长系数场景 200.182 ms 内保守拒绝证明，未超过 3 秒外层期限；超维度形状在搜索前拒绝。该现有用例打印的 p95 为第二大样本，与本报告其他表的 nearest-rank 不同。

## 频道网络

使用真实 AE2 `GridNode` / `GridConnection` 与生产 `assignChannels`，图形和设备 owner 是夹具；不加载游戏世界或 Mixin 回写。20,000 个随机图的总流量与独立增广路最大流一致，额外检查无线限流、物理连接、多方块、禁止转发、无限模式、容量切换与断开重连。

每个大型场景独立 JVM，预热 3 次、测量 12 次。计时不含图构造和校验。下面没有与历史 alpha/JDK 21 的性能数据混算。

| 场景 | 节点数 | 需求/实得频道 | p50（ms） | p95（ms） | 分配（MiB/次） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 高容量树 | 226,898 | 136,192 / 136,192 | 526.902 | 855.406 | 105.701 |
| 致密容量树 | 226,898 | 136,192 / 136,192 | 558.900 | 747.274 | 105.701 |
| 网格 | 272,650 | 136,192 / 136,192 | 1,077.348 | 1,699.521 | 137.858 |
| 原版控制器面 | 226,898 | 136,192 / 136,192 | 493.840 | 570.061 | 105.945 |
| 加权设备 | 532 | 136,192 / 136,192 | 2.517 | 4.337 | 0.266 |
| 20,000 层链 | 20,267 | 1 / 1 | 19.326 | 27.719 | 9.134 |
| 10,000 支梳形链 | 20,266 | 10,000 / 10,000 | 37.003 | 59.385 | 9.069 |
| 超额需求树 | 290,706 | 200,000 / 136,192 | 852.227 | 1,278.432 | 130.782 |

全部容量检查通过，1 MiB 线程栈下深链未溢出。网格的堆池峰值合计约 615 MiB，12 次测量期间 GC 总计 91 ms。夹具的堆池峰值相加不是进程 RSS。极端图耗时超出 50 ms 刻预算，仅能说明单次求解成本，不是实机 TPS 测量。

压测发现 `ChannelStress.main` 独立执行缺少 Minecraft bootstrap，导致物品注册表初始化失败。已补齐与 `AlgorithmComparison` 相同的初始化；修正后的仓库入口另运行 100 图 oracle 与特殊场景通过。

## 索引存储

每组 10,000 个不同 NBT 的 AE2 物品键，普通 long 数量与 150 位精确数量分别进行 120,000 次测量插入/提取；每组另有 30,000 次预热操作。每批保存并回读，与独立数量表比对；最后删除 8,000 键强制压缩、再插入并比对。

| 场景 | 操作 p50（µs） | 保存 p50 / p95（ms） | 读入 p50 / p95（ms） |
| --- | ---: | ---: | ---: |
| 普通 long | 0.386 | 0.284 / 0.545 | 23.397 / 42.956 |
| 150 位数量 | 1.182 | 3.858 / 9.241 | 20.923 / 49.623 |

操作计时包含独立 HashMap/BigInteger 参考表更新，因此不能当成纯存储 API 微基准。独立 JVM 未运行 AE2 的 Forge 键类型注册，第一次通用解码无法恢复键；使用明确的 `AEItemKey.fromTag` 解码器后，全部数量、压缩和重插入一致。该结果验证存储引擎及 NBT 数量布局，不代表完整模组生命周期的注册与磁盘 I/O 压测。
