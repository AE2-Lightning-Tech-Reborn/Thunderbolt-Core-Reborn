# GTL 规划器与频道分配优化（2026-10-05）

本次针对上一轮压测中的三配方混合回退和大型频道图分配开销优化，比较基线为 `4907d4f`。环境为 Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10、Java 17.0.20；测量 JVM 使用 `-Xms256m -Xmx2g -Xss1m -XX:+UseG1GC`。

## 修改与正确性条件

JFR 显示，三配方查询主要时间花在通用优化器重复进行批次枚举与物料回放。局部精确搜索只在原方案的用料限制内证明最优，不能直接据此跳过允许更多库存的通用搜索。

现在额外接受一个严格证书：局部搜索完成并返回新方案，目标没有库存，全部目标配方都是单位执行成本、直接消耗普通原料，且执行次数等于 `ceil(请求量 / 最大单次产出)`。更多库存无法突破这个执行次数下界；同执行次数的逐项用料改进又一定落在原方案用料限制内，已经被局部精确搜索覆盖。目标库存、副产物、零成本转换、状态输入、可生产的中间输入，以及未完成或保留原方案的局部搜索继续使用原有通用优化路径。

频道剖析显示临时连接记录占有明显分配量。每条连接现在只保留 `GridConnection` 引用，从连续的四条残量边读取流量和端点，避免逐连接分配记录对象，并预分配引用列表。双向种子、精确剩余最大流、并行连接、无线限流、环流消除和回写数据结构保持原有行为。

GTL 的 `computePlan` 接入、计算调度轮询及 CPU 让位逻辑保持原有行为。

## 复测

最终独立运行结果见 [统计 JSON](benchmarks/gtl-optimization-20261005.json)。原始 JFR、夹具、类快照、日志和启动脚本保留在忽略目录 `build/optimize-20261005/`。先前与完整回归测试部分重叠的探索测量单独留档，最终结果采用回归及 GameTest 结束后的串行测量。原有桌面与游戏进程未停止，因此时间仍会受到系统负载影响。

三配方夹具为铁、钻石各库存 100，三条路线分别是 `(铁2 + 钻石2) → 目标2`、`铁7 → 目标4`、`钻石7 → 目标4`，请求 10。每个版本运行 5 个独立 JVM，交替顺序；每个 JVM 预热 2,000 请求，测量 40 组，每组 50 请求。每次检查可行性、3 次执行、铁和钻石各用 9。

| 三配方指标（各 JVM 统计的中位数） | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| p50（µs/请求） | 179.720 | 37.704 | -79.0% |
| p95（µs/请求） | 361.498 | 65.028 | -82.0% |
| 分配（B/请求） | 153,824 | 31,248 | -79.7% |

各 JVM 的 p50 范围分别为 134.750–269.080 与 33.390–64.438 µs。另一组探索测量也得到约 80% 的下降，原有性能回退在此夹具中已消除。

频道复测采用真实 AE2 节点与连接，前后各 3 个独立 JVM，交替顺序，每个图预热 3 次、测量 12 次。计时不含图构造与结果校验。12 样本的 nearest-rank p95 等于最大值；堆池峰值合计不是进程 RSS。

| 频道图 | 节点 / 连接 | 前/后 p50（ms） | 前/后 p95（ms） | 前/后分配（MiB/次） |
| --- | ---: | ---: | ---: | ---: |
| 高容量树 | 226,898 / 226,897 | 657.807 / 555.095 | 1,103.187 / 777.675 | 105.701 / 95.163 |
| 网格 | 272,650 / 408,368 | 717.000 / 775.930 | 811.270 / 908.565 | 137.858 / 118.697 |

树形图的 p50 中位数下降 15.6%，但各 JVM 范围仍重叠。网格的 p50/p95 中位数增加 8.2%/12.0%；探索组中网格中位数反而下降 27.8%，独立组的前后 p50 范围为 684.580–1,101.717 / 655.370–1,049.360 ms。因此不宣称网格稳定提速，保留此处实测回退。稳定收益是树/网格的分配量分别下降 10.0%/13.9%，每次求解都取得 136,192 频道并通过守恒验证。

大型规划图继续使用默认工作预算、15 秒合作取消期限和独立原始样板 DAG 回放；每版本测量 240 请求，超过准入上限的 12 请求按预期返回预算耗尽。

这些普通 DAG 不进入本次修改的可选优化阶段，结果与分配保持原有量级；完整六场景数据保留在 JSON 中，不将其时间波动归因于本次优化。

## 验证范围

新增 400 组随机三/四路线与独立枚举比较，验证证书不能漏掉更多库存带来的执行次数改进，也不能漏掉同次数逐项用料改进。另覆盖未完成搜索、保留原方案和额外目标库存。

频道额外运行 20,000 随机图，与独立增广路最大流比较；验证无线、物理、多方块、禁止转发、无限模式、重复供给、断开重连与并行路径。所有大型夹具验证流量、节点容量及连接守恒。

完整单元测试共 1,289 项：1,288 通过、1 项可选运行时测试跳过、0 失败。单独 JVM 的冷启动 CP-SAT、发布 Jar/refmap 校验和强制 `gtlCompat=always` 的 10 项 Forge/AE2 GameTest 通过。GameTest 使用隔离世界和受控机器输入，没有加载 GTLCore/GTCEu/AE2LT 完整整合包。

产物 `build/libs/thunderbolt-forge-1.20.1-2.0.0.jar`，SHA256：`bbbd91ab8626b88d82c64e37988974cc0b0faa6ab8bcebf529048de3c6615fe0`。

该结果说明查询与单次频道求解的成本，不能推导整合包 TPS 或真实工厂吞吐。极端频道图仍明显超出 50 ms 刻预算。
