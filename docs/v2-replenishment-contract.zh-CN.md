# V2 补料后可执行性实验

本轮以 Reborn `1f8d690` 为基线，修复多环方向组合和缺料来源归因，并为普通物料图建立可重复的补料保底。保留上游的稀疏有理数优化、执行输入分配和超量精确预览。

## 外部目标与当前范围

优先级为：不接受不能执行的可行计划；报出的完整补料应足以完成请求；计算预算耗尽应尽可能仍给出可用结果；最后才降低误报缺料和额外补料量。预算耗尽、方向未遍历和局部不支持属于内部诊断，不能作为真实缺料或全局无解的证明。

本轮新增的补料保证覆盖：默认切环后形成 DAG、所有候选均为普通消耗输入、无副产物和宿主私有库存、各项累计需求小于 `Sat.SAT` 的图。原图可以含普通转换环；被切断且无剩余生产路线的物品仍作为该路线的叶子。

以下范围仍沿用原路径，**本轮没有证明整个 V2 在所有情况下都满足上述目标**：

- returned 催化剂、宿主库存、容器返回、副产物和闭环宏仍依赖原有启动及执行回放；不能用普通物料的单调性替代它们的顺序约束。
- 整图导出上限、宿主匹配上限和外层 attempt 墙钟仍可能在生成本轮保底前退出。外部取消继续传播，不作为可忽略的预算事件。
- 超量仍沿用上游 `ExactDiagnosticPlanner` 和底层精确数量显示；不把超量缺料改为中间品，也不把精确预览当作可提交执行证明。

## 为什么需要固定路线

只有“当前配方次数加上 Missing 可以执行”还不够。玩家补料后会重新计算，动态容量排序可能改选另一组配方，又报告新的缺料。基线的一个普通 DAG 在搜索预算为 1 时先报告 `M6=15, M7=3`，补齐后改为报告 `M6=17, M7=3`。

`ConservativeReplenishment` 为默认切环图编译固定配方策略。它按稳定顺序与估计原料成本选取每个产物的一条路线，选择不依赖库存和请求数量。成本只负责选择路线，不能作为可行性证明。执行次数与聚合需求使用精确整数计算，超过本轮可执行范围立即交回既有超量路径。

对于固定的普通 DAG，若库存从 `S` 增加到 `S+Δ`，从目标向原料传播时，每个节点的需求不会增加：

1. 目标需求相同，额外库存只会减少未满足需求。
2. 固定配方的批次数是未满足需求的向上取整，因而不会增加。
3. 所有输入系数非负，没有因减少生产而消失的副产物信用。
4. 按拓扑顺序归纳，上游需求均不会增加。因此补齐此策略报告的所有叶子缺料后，该策略必然可行。

原有规划器仍先寻找更好的可行计划。需要返回缺料时，候选清单只有在也能使固定策略可行时才保留，否则返回固定策略的完整计划和缺料。固定策略清单逐项更少时优先返回它。它提供缺料优化开始前的稳定保底；后续缩减只接受实际补料重算已验证成功的清单，见下一节。

一次 calculation 只编译一次默认策略；不同数量探测重新计算需求和库存使用量。超量探测不能使后续较小数量失去保底策略。正常线性成功路径不进入此新增流程。

## 在预算内消除被支配的缺料

`MissingRefinement` 在现有清单内部逐项向下搜索，不增加另一种材料来交换当前材料。每项先尝试减少一份；成功后按几何步长继续减少，失败后在已知成功与失败的区间内二分。不按请求份数逐份枚举，也不维护指数规模的完整 Pareto 前沿。

每个候选使用“原库存 + 完整候选清单”调用真实 V2 重新规划，显式使用最小的 visit/search 额度。只有支持且可行、Missing 为空的结果才接受，并保留该次完整配方次数；其实际库存提取被拆回原库存和待补材料。候选中尚未用到的材料也不能直接删掉，因为删后可能改变下次选路，必须另做一次探测。

探测不递归调用缺料优化。它共用 calculation 的整数求解、搜索、fallback 和状态解析预算，每次还按整张可达图工作量扣搜索预算；每个 calculation 最多 24 次探测，后续数量试算不能重置次数。该可选阶段累计最多请求 100 ms，并至多使用当前外层剩余时间的四分之一；通过现有协作检查退出，保留最近的有效清单。它仅捕获自己的可选阶段超时，外部取消和路由层退出信号继续传播。

补料后的容量与库存相关，不能复用原 `PreparedGraph` 的旧容量；图快照中的不可变配方可以共享。原始搜索统计仍记录主规划，新增 `missingRefinementProbes`、`missingRefinementImprovements`、`missingRefinementNanos` 单独记录补料优化，搜索消耗包含探测工作。

无切环且无配方竞争的普通 DAG 无须此搜索。对于所有主产量均为 1 的普通无环图，编译阶段的原料成本还给出一个通用势函数：每条配方满足 `c(output) <= Σ c(input)`。因此额外补料的加权量至少为 `max(0, c(target)*Q - Σ c(item)*stock(item))`。若当前清单达到下界，且清单各项权重均为正，则不存在逐项不增加、至少一项减少的替代清单，可以立即结束。这条证明不依赖物品名、Fib 结构或固定系数；整数批量产出不使用这条单位产量证明。

32 层双路线 Fib、库存 `X0=X1=X2=1` 的原结果为 `X1=3328,X2=4409`；现在返回 `X1=2512,X2=3327`。总补料 5839，达到此实例的下界 `5842-3`。无库存版本仍为总量 5842，并直接由下界结束。

一般情况下仍只声称“在预算内找到的、实际验证过的更小清单”。一次尝试失败可能是启发式假阴性，达到次数或时间上限也不代表已证明 Pareto 最优。新的收缩阶段仍只接入普通物料保底覆盖的范围；带 returned、副产物、宿主私有库存的补料不在本次扩大范围内。

## 切环搜索

原来的候选每次只改变一个 SCC，无法同时修复两个独立环。现在保留其他 SCC 已选的根，只替换当前 SCC 的方向；每次重算完整计划，不能拼接不同候选的库存消耗。

缺料可能落在环外：切错方向迫使 `E` 采用 `D -> E`，最终显示缺 `D`。现在沿实际使用的配方把缺口归因回环内产物，从而继续尝试相关切环方向。这个归因仅决定探索顺序，不增加库存或接受未经验证的执行次数。

仍然最多进行 16 次额外尝试，并共用搜索与精确求解预算。每次最多生成 16 个候选，去重后深度优先探索，不展开所有 SCC 方向的完整组合。未访问或被截断的方向会标记内部 cutoff。

## 验证与成本

- `CombinedCycleOrientationTest`：2/3/8/16 个独立环、所有两环根输入排列、样板登记顺序、复杂 SCC、压缩链、共享原料、库存不足、数量探测及第 17 个环触发上限。
- `ReplenishmentContractTest`：环外原料缺口的两个输入顺序；500 张普通 DAG；500 张普通循环图；超量探测后的小数量重算。
- 属性测试使用独立 `BigInteger` 收支核对，再仅用计划声明的库存和 Missing 实际执行全部配方次数；最后建立补齐库存的新图重新规划。判断器不复用 `Sat` 或生产需求计算。
- 初版 Java 21 全量测试：546 项通过，0 失败、0 错误、0 跳过。后续收缩新增 `MissingRefinementTest`，覆盖部分库存 Fib、100 张随机 DAG 的精确收支和最小预算补料重算、十亿请求、共享数量探测额度和取消/可选超时边界。
- 收缩版 Java 21 全量测试及完整构建：554 项通过，0 失败、0 错误、0 跳过；其中还新增了严格守恒但初始死锁的环回归，见 [非自增环直接求解的边界](non-growing-cycle-solving.zh-CN.md)。
- Alpha 同时修复[精确需求与动态同 ID 产物混用](mixed-demand-allocation.zh-CN.md)，以及同一任务内模糊槽先取精确库存的问题；完整构建共 564 项测试通过，0 失败、0 错误、0 跳过。

与 `1f8d690` 使用同一驱动和其余 core 类对比，500 张固定随机 DAG 的补料重算失败从 5/500 降至 0/500；初次可行均为 113/500。平均清单数量从 9.992 增至 10.136，增加约 1.4%。这是测试集合上的补料结果，不能解释为实际整合包的假阴性率。

新增策略编译及一次需求传播均为 `O(V+E)`，空间为 `O(V+E)`；候选清单已覆盖保底清单时，无需额外传播。工作不随请求份数逐份展开，没有扩大整数求解和切环次数上限。失败路径会增加常数成本，并可能返回比原启发式更多的材料，以换取已覆盖范围内的补料确定性。

后续收缩版与本地初版 `1614dd1` 独立比较，三组 JVM，每例预热 20 次、测量 40 次：500 层已备料链中位数为 1.959→1.983 ms，缺料链为 2.155→2.375 ms；零库存 32 层 Fib 为 0.241→0.245 ms；部分库存 Fib 为 16.914→38.196 ms，补料总量为 7737→5839。此组基准与上表预热条件不同，应只做组内比较。缺料质量改善需要额外规划验证，并非免费；它受同一预算与可选阶段上限约束。
