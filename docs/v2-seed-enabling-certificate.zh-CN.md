# V2 第六轮：种子返还仍保留启动依赖

把随机图扩为 7 种物料、14 个配方、请求 2 件后，发现 3 个存在执行顺序但不能保证任意启用顺序的旧计划。正常单步可达性检查会放过它们；独立全顺序检查找到确定死锁前缀。

原因：无序执行证书把会返还的输入转换为净消耗时，也删掉了启动依赖。后续生产者因此能在纸面上补回它自己启动所依赖的种子。修复只保留原输入的依赖边，数量余额仍按净消耗计算；启动环不能被这个代数化操作隐藏。

新增直接证书回归，数量从 1 到一万亿，无按数量循环。693 项测试通过。原 113000 样本可行性与缺料向量完全不变；新增 10000 个请求 2 件和 30000 个请求 3 件的图，全部初始/补料计划通过独立全启用顺序验证。共 153000 个初始计划、42681 个补料计划，零失败/未知。3 个危险计划现在要求安全种子，补齐后可行。

该验证范围为普通消耗/副产物图；工具、容器、私有复用池沿用各自语义。超量仍遵循原有策略。未推送，未合并 alpha。
