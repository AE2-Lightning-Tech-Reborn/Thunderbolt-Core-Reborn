# Forge 1.20.1_GTL：压测与缺料诊断审计

本轮在 `5985d3108d335f6b206ab617245732bde08bf7c4` 上发现四类问题：模板种子错误预留、ID_ONLY 输入组合展开导致漏解、CP-SAT 共享种子补货的间歇性漏解，以及大副产物图的未完成方案未标记预算耗尽。前两类有稳定复现；后两类有实际失败样本，根因与出现频率仍需继续验证。

测试环境为 Minecraft 1.20.1、Forge 47.1.3、AE2 15.4.10、Java 17.0.20。每个测试 JVM 使用 256 MiB 初始堆、2 GiB 最大堆及 4 个活动处理器。当前代码树与锁定上游 `AE2-Lightning-Tech-Reborn/Thunderbolt-Core-Reborn` 的 `1.20.1_GTL` 提交 `d1733e0` 相同。本轮增加审计文档和数据，生产代码尚未移植或修复。

## 复现结果

### 1. 已有模板被不必要地预留为启动种子

图中有模板复制配方时，即使普通库存中的模板足够直接合成目标，`reserveSelfSeed` 仍先扣留模板。普通与私有库存的种子协调，以及私有种子被其他路线占用后的转换配方回退，也存在误报缺料。

具体例子：普通库存有 1 个模板，私有库存为 0，请求 1 个目标。目标消耗 1 个模板、1 个镐和 1 个锭；镐所需的 3 个钻石可以用充足矿石制造。模板复制配方每次消耗 7 个钻石并返还启动模板。当前版本报告额外缺少 7 个钻石，而正确方案直接消耗已有模板，不执行复制配方。

矩阵枚举私有库存 0–2、普通模板库存 0–3、启动种子 1–2、请求量 1/2/5、现有钻石 0/7/10，以及两种根输入顺序，共 432 个组合。预期可行条件独立计算为 `stock >= quantity || host + stock >= seed`；可行方案另行核验物理库存、种子启动条件和矿石至目标的资源见证。

| 版本 | 独立 JVM 数 | 每轮误报缺料 | 错误可行判定 | 无效资源见证 | 预算退出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 当前 GTL | 3 | 224 / 432 | 0 | 0 | 0 |
| 隔离上游修复对照 | 3 | 0 / 432 | 0 | 0 | 0 |

上游 `SelfSeedReservationTest` 的 8 项测试在当前版本失败 6 项，对照版本全部通过。对应上游修复为 `eec7b4d`。

### 2. 同 ID 多变体输入展开丢失可行路线

`FastCraftingPlanner` 把多个 ID_ONLY 输入槽的候选展开为配方组合。6 个槽的复现图已经生成 64 个消费者配方；7、8、18 个槽的图在各原料都有生产配方且库存充足时，无法给出执行方案。4 个槽、单槽数量 100000 或 3000000000 也能复现；CP-SAT 路径同样受图导出影响。

另一最小例子：一个 ID_ONLY 输入槽需要 100000 件同 ID 材料，三个具体 NBT 变体分别有 30000、20000、50000 件。总库存恰好足够，当前版本仍无法给出方案。

上游 `FastCraftingPlannerIdOnlyCraftableVariantTest` 共 35 项在当前版本失败 9 项，其中 1 项是消费者配方数量膨胀断言，8 项是可行方案缺失；隔离对照全部通过。对应上游修复为 `65eb47a`。对照还覆盖严格输入、混合输入、不同单位大小及精确预览，避免用错误共享库存来通过上述用例。

### 3. CP-SAT 宣告的共享种子补料不能稳定兑现

两条独立循环各消耗一个 `S` 作为启动材料，循环使用 `R` 并返还各自的 `A`。库存 `S=1、R=6`，请求 `T=3` 时，首次求解正确报告缺少 `S=1`；加入该缺失量并使用新的默认会话求解，仍可能返回不可行计划。

原有 `CpSatExecutionBlocksTest.independentCyclesShareTheSamePhysicalSeedMaterial` 在全量运行失败；独立 JVM 复测失败 1/3，隔离上游对照通过 3/3。新增 `freshDefaultSessionsReplanTheSharedSeedSupplement` 从 `S=2、R=6` 开始，也在当前版本报告缺少 `{A1=1,A2=1}`；对照完成了该测试要求的 8 次新会话求解。

这一结果证明当前有界求解会漏掉实际可执行的补料方案，尚不能解释为数学上的不可行证明，也不能把 1/3 当作长期故障率。对应上游 PR #12 的最终 CP-SAT 改动；有效范围为 `65eb47a..3671870`，其中已撤回的 V2 改动不在该净差异中。

### 4. 大副产物图返回缺料，但未标记预算耗尽

4096 个分支、请求量 10¹²，在 3 个独立 JVM 的 15 个测量样本中，出现 1 次未完成方案：耗时 **9124.323 ms**，缺失 **4096** 种物料，`budgetExhausted=false`。同场景的 3 次预热全部完成。该失败样本保留在结果中。

夹具库存充足，有独立的 `BigInteger` 供给顺序重放见证；完整计数向量的独立证书在两种请求量下共 72 个测量样本及 18 次预热全部通过。未完成方案加入其声明的缺失物料后也通过重放，这仅验证其声明的补料足够，不代表原方案正确识别了真实缺料。

失败诊断中记录 1385 次分量求解尝试、1384 次完成，搜索、解析和回退的截止标记均为 false，外层调用截止时间为 15 秒。可选阶段中途退出与保守缺料的标记需要继续追踪；本轮未证明该现象的具体根因，也未证明上游对照能消除它。

首次全量失败导致后续冷启动及发行检查未执行，因此另行补跑：`cpSatColdRefinementTest --rerun` 的 1 项测试通过，`verifyReleaseJar` 的 Jar、Mixin refmap、配置与 JarJar 元数据检查通过。

## 上游对照和修复顺序

对照来源为普通 `1.20.1` 的 `367187056040f0f99b2491a3df94ab0dc2302046`。以当前 GTL 源码的隔离副本应用 `73b88cf..3671870` 的生产代码净差异，保留当前 GTL 改动；独立编译后将其类目录置于当前运行时类路径首项。原有 `73b88cf` 的改动已经存在于 GTL。

上游测试仅重命名类以便独立发现。`CpSatSeedPortfolioRegressionTest` 的新 API 结构测试无法直接编译在当前版本上，故对照只取公开行为测试 `freshDefaultSessionsReplanTheSharedSeedSupplement`；没有修改该测试的断言或预算。

建议先移植模板种子、ID_ONLY 分组与 PR #12 最终 CP-SAT 修复，并在 GTL 环境完成全量及集成验证；随后追踪大副产物图的可选阶段退出和缺料标记。隔离对照尚未完成候选版本全量验证，前三类定向通过不能代替正式移植验证。

完整测试逐项结果、独立复测、2592 条矩阵记录、压力原始采样及未完成诊断见 [验证数据](validation/gtl-bug-audit-20261007.json)。本机日志、临时类路径与进程信息仅留在忽略的本地构建目录。
