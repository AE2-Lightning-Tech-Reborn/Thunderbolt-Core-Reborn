# 堆叠上限缓存简化

2026-09-20，在 `1dbd09d` 的对象复用实验上删除堆叠上限的逐次复核。

## 行为

- 新建 AEItemKey 时仍由原生构造器计算堆叠上限，保留 NeoForge 自定义钩子。
- 同一物品、组件及模板快照命中缓存时，不再调用 `getMaxStackSize()`。
- 普通缓存和组件身份缓存移除堆叠上限比较；组件内容探针移除对应字段、hash 项及比较。
- 仅覆写堆叠上限钩子的物品也能使用 Item 字段快路。自定义耐久钩子的识别及核验保持。
- 组件改变后按新的快照查找或构造；原键仍保存旧快照。数量／动画继续归一化为 1／0，调用者的物品栈不变。

不再保证“物品和组件都没变，仅外部变量或配置改变”时，下一次查询能发现新的堆叠上限。缓存清空后仍会在新构造时重新计算。历史对照表中的 64→16 外部变量探针保留历史观测，但它是人工边界测试，不能作为真实附属故障的证据。

## 验证

- 875 项 JUnit：失败、错误、跳过均为 0。
- 七附属联合 37 项真实 Mixin GameTest：修正测试预热后连续四个独立进程全部通过；覆盖的附属版本仍见 [jar 清单](object-reuse-tested-artifacts.json)。
- jar 构建成功。
- 将外部变量突变测试替换为组件快照测试：自定义钩子的返回值特意不同于原生组件值，确认首次构造没有绕过钩子；组件更改后得到新上限；普通、组件身份和独立等值内容命中不再调用该钩子。
- 新增原生 `MAX_STACK_SIZE` 组件 64→16 的区分和复用检查，保留既有数量敏感钩子归一化测试。

第一轮有两个失败：新增测试没有预热首次可写组件快照，已修正；原有 GC 实例保持测试失败的同一时刻，日志记录到 `thunderbolt-common.toml` 自动重载，现有配置处理会主动清空缓存，因此该轮不满足“同一缓存代”的测试前提。配置稳定后的连续四轮保留原断言并全部通过，没有修改生产缓存的换代／GC 逻辑。

## 同基线性能

Minecraft 1.21.1、NeoForge 21.1.219、AE2 19.2.17、Temurin 21.0.11+10、arm64。每版三个独立 JVM，按 BEFORE 三次、AFTER 三次顺序串行执行，无并行争用。性能进程不加载七附属，每次均通过运行宿主检查，没有检测到测试期间的配置重载。

每场景 8 轮预热、9 轮测量、每轮 20 万次，取每进程中位数，再取三个进程的中位数。使用同一公开 `AEItemKey.of` 入口和 volatile sink；分配为当前线程分配量，不是存量堆大小。自定义钩子物品来自固定测试样本，不代表整包物品的占比或 TPS。

| 场景 | 修改前 ns/次 | 修改后 ns/次 | 修改前→后 B/次 |
| --- | ---: | ---: | ---: |
| 普通铁锭 | 2.485 | 2.578 | 0→0 |
| 自定义堆叠钩子，数量 1 | 17.969 | 2.231 | 0→0 |
| 自定义堆叠钩子，数量 64 | 24.955 | 3.110 | 72→0 |
| 自定义堆叠钩子，组件命中，数量 64 | 29.722 | 9.250 | 56→0 |
| 每次新建等值组件栈 | 114.699 | 102.453 | 552→528 |

普通铁锭没有体现加速；其原有快路已经没有逐次堆叠上限核验。明确改善集中在仅因自定义堆叠钩子而走复核路径的命中场景，尤其省去了为检查元数据而复制归一化栈的分配。

最后一行包含创建栈和组件的成本，前后进程范围分别为 104.159–114.888、101.916–130.126 ns；两版分配也都出现过 528 和 552 B，不能据中位数宣称稳定加速或稳定减少 24 B。
