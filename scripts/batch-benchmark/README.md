# 批量库存压力校验

使用 Java 17、Python 3 和当前 Forge 1.20.1 的测试运行类路径：

```sh
./gradlew --no-daemon -I scripts/batch-benchmark/classpath.init.gradle writeBatchBenchmarkClasspath
python scripts/batch-benchmark/run.py
```

默认启动三个独立 JVM，种子为 20261008、20261009、20261010。每个 JVM 验证：

- 20,000 个随机具体输入分配：1–6 个槽位、重复物料、非单位模板数量、受保护库存、万亿数量、容量拒绝/截断/超额返回/异常。
- 准入时只抽取一份原型；最终抽取遵守库存和容量；部分派发后只退回未接受输入；重复退款不会增加库存；临时容量作用域被恢复。
- 2,000 个多提供者案例：1–8 个提供者、独立准备容量、部分接受、CPU 数量预算、任务进度、等待输出和最终库存守恒。

Oracle 直接从固定输入分配和初始库存计算数量，不调用规划器推导期望值。提供者回调中的断言被另行保存，防止生产代码捕获准入异常后产生假通过。

结果与 JVM 日志仅保存在忽略目录 `build/batch-benchmark`。可使用 `--seeds 123 456` 指定种子，或 `--classpath <file>` 使用其他已生成的当前运行类路径文件。固定案例数量和所有断言保持相同。

夹具使用现有测试的 `TestKey`，直接调用生产批量抽取和执行代码。它验证库存与协议所有权，不代替整包服务器 TPS 或真实机器兼容性测试。
